## 3. 需要你重点确认的争议点

### 3.1 彻底删除 vs 功能迁移

矩阵中有 120 条 FOLD。删除是彻底删除：

- 从 registry、pageComponents、pages barrel、组件文件、旧测试、catalog、config 中移除；
- 后端仅为该入口存在的路由与 OpenAPI operation 一并删除；
- 不保留旧 URL 重定向；
- 能力必须先迁入目标页面的 Tab、动作或详情分区。

请确认：**是否接受旧 URL 直接 404**，以及是否接受删除 `PlatformWorkspace`、`PeopleWorkspace`、`TimePayrollPage`、`TalentWorkspacePage` 这些旧共享壳。

### 3.2 六张截图页面的最终归属

| 截图 | 最终位置 | 关键改动 |
|---|---|---|
| 部门人数分析 | `/dashboard` 的“部门人数”分区 | 删除独立页；指标中文、单位正确、可下钻 |
| 假期规则 | `/leave?tab=policies` | 新增版本表与 append/retire 写命令 |
| 薪资项目 | `/payroll?tab=components` | 新增 `payroll_item_versions` 与版本/停用命令 |
| 角色管理 | `/system/roles` | 保留四 Tab；去 ADR/技术码；新增 `/system/pages` |

请确认这些归属，尤其是“薪资项目”放在 `/payroll` 内而不是单独侧栏。

### 3.3 新增写命令与迁移

计划中明确标注为新增的主要有：

- M10：`leave_types` 写命令、`leave_policy_versions` 迁移、规则 append/retire、代申请；
- M11：`overtime_policy_versions` 迁移与写命令；
- M13：`payroll_item_versions` 迁移与版本/停用写命令；
- M21：`GET/PATCH /v1/system/company-profile`、`GET /v1/audit/events`、导出；
- M02/M03/M04/M09/M12/M15/M16/M17/M18：若干参数或读模型扩展。

请确认：**允许为闭环新增这些前向迁移与写命令**，而不是只做前端改造。

### 3.4 权限与数据范围

- 角色授权继续走单一原子端点 `PUT /v1/roles/{id}/authorization`；
- 页面进入权与按钮动作权保持独立；
- 每个写动作必须有 403 负测；
- 撤销权限后旧标签页再次提交必须失败；
- 字段策略覆盖证件、联系方式、工资与导出。

请确认：**是否接受“隐藏按钮不是安全边界”作为所有模块的硬约束**。

### 3.5 真实证据门槛

每个模块退出必须提供：

- 后端 feature/契约测试；
- 前端单元/E2E；
- 真实数据库与浏览器截图；
- `pnpm gate:all` 实际输出；
- 未执行项标 `NOT RUN`。

请确认：**是否接受“没有真实执行证据不得判模块完成”**。

## 5. 已知风险与执行边界

1. 计划量大：21 份约 6000 行，执行时必须按 D0–D8 分批，不能并行改共享契约。
2. 页面计数跨模块递减，已要求使用 `scripts/v23-page-count.json` 单一基线，禁止各模块从 155 重算。
3. 删除旧壳会影响大量旧测试与快照；必须先迁移能力、再删测试、最后删代码。
4. 新增写命令必须复用现有 `CommandRunner`、幂等键与审计，不得另造旁路。
5. 真实栈 E2E 受本机环境限制；未执行时模块必须 `BLOCKED`，不得以静态门禁替代。
