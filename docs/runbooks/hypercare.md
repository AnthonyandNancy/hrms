# HRMS V1.0 90 天 Hypercare Runbook

> 文档性质：本仓库是 HRMS V1.0 的参考实现，本文件定义 Hypercare 的组织、值班、对账与退出基线。
> 所有生产指标、值班表、告警路由、签字和真实环境演练均为 **GATE**；未执行的验证只能标记 **NOT_EXECUTED**。
> 切换步骤见 `docs/runbooks/cutover.md`；回滚步骤见 `docs/runbooks/rollback.md`。

## 0. 目的与时间盒

Hypercare 是分域切换完成后 **90 天**的强化运营期，目标不是“功能更多”，而是让人事、假勤、工资在真实月度里可解释、可对账、可回滚。

| 阶段 | 时间 | 重点 | 会议/产出 |
|---|---|---|---|
| H0 进入 | 切换完成当天 | 确认切换 exit、值班表、告警路由、回滚点 | 交接记录（**GATE**） |
| H1 前 2 周 | D1–D14 | 高密度监控、工资/假勤首周期、用户支持 | 每日 Hypercare 战会（计划 10.3） |
| H2 第 3–8 周 | D15–D56 | 稳定化、工单下降、对账节奏 | 每周复盘 + 每月指标 |
| H3 第 9–13 周 | D57–D90 | 退出准备、技术债/手册/演练补齐 | 30/60/90 天复盘 |
| H4 退出 | D90 或更晚 | 计划 12.2 全部满足后退出 | 发起人批准（**GATE**） |

计划 12.3 要求 30/60/90 天复盘；90 天不是自动退出日，未满足退出条件则延长 Hypercare，不得用“到期”代替达标。

## 1. 严重度矩阵（与审计文档第 5 节一致）

分级定义来自 `docs/10-joint-audit-acceptance.md` 第 5 节与计划 5.4；Hypercare 只在其上补充响应节奏。**Sev1/Sev2 未关闭即阻断发布/验收；Sev1 一票否决。**

| 等级 | 定义（审计文档原文口径） | 典型 HRMS 例子 | 响应目标 | 修复 SLA | 发布/验收影响 |
|---|---|---|---|---|---|
| **Sev1** | 数据泄露、工资错发、账本错账、不可用 | 越权读取员工/工资数据；工资已付款金额错误；假勤/工资账本不平且影响付款；核心系统全面不可用；密钥/凭据泄露 | 立即响应；MTTA ≤15min；MTTR ≤4h（计划 12.1） | 4h 内缓解；根因修复另排 | 阻断发布，必要时按 `rollback.md` 回滚；一票否决 |
| **Sev2** | 核心流程不可用、权限错误、迁移对账失败 | 入职/合同/假勤/工资核心流程无法完成；越权访问；迁移人数/组织/合同/工资总额对账失败；账本/权限错误 | 立即响应；1 个工作日内修复（计划 5.4） | 1 个工作日内 | 阻断发布/对应波次 Go；不得带病进入下一波 |
| **Sev3** | 非核心错误、体验问题 | 非关键页面报错、导出体验、通知延迟但不影响事实正确性 | 当前 sprint 内处理 | 当前 sprint | 可带计划发布；必须有 owner 和日期 |
| **Sev4** | 文案、样式、建议 | 文案错别字、样式、交互建议 | 排期处理 | 排期 | 不阻断；不得占用 Sev1/2 容量 |

补充规则：

- 同一事件可升级：数据可能泄露、工资可能错发、账本可能不平、或影响范围扩大时，立即升级为 Sev1/2，不等确认完整根因。
- 不确定是否工资错发时，默认按 Sev1/Sev2 处理并冻结付款；不得先付款后核实。
- 只有技术负责人 + 业务 owner + 安全/财务（按影响）共同确认后才可降级；降级记录写入事件单。
- Sev1/2 修复必须附证据（测试、对账、审计、回滚/更正记录），不能只写“已修复”。
- 事故复盘：每次 Sev1/Sev2 必须复盘，产出根因、行动项、责任人和期限（方案 14.3）；组织时限为 **GATE**。

### 1.1 升级触发线

| 信号 | 初始等级 | 升级动作 |
|---|---|---|
| `/v1/health/ready` 连续 503 或核心用户不可用 | Sev1/Sev2 | 立即召集 IC、DevOps、DBA；评估回滚 |
| 工资差异 > 0.01 元、人头不一致、已付款错误 | Sev1 | 冻结付款/发布，财务与法务加入，启动更正或回滚评估 |
| `ledger:reconcile` 非零或账本不平 | Sev1/Sev2 | 停止关账/工资输入，HR/财务对账 |
| 越权/IDOR/字段泄露/旧会话未失效 | Sev1/Sev2 | 安全加入，撤销会话/权限，保留审计，评估泄露通知（**GATE**） |
| 迁移对账失败、孤儿/重复/映射丢失 | Sev2 | 停止切换/发布，回退波次，数据 owner 对账 |
| P95 > 500ms 或错误率 > 0.5% 持续 | Sev2/Sev3 | 查依赖/队列/DB；影响工资/关账即升 Sev1/2 |
| 导出泄露 HIDDEN 字段、短效链接失效/越权 | Sev1/Sev2 | 撤销链接、审计访问、按泄露流程处理（**GATE**） |
| 备份/PITR/恢复演练失败 | Sev2（发布前为阻断） | 暂停发布；DevOps/DBA 补齐，不能以“下次再练”关闭 |

## 2. 值班与升级（On-call / Escalation）

本仓库**没有** PagerDuty、短信、电话、Slack 或邮件路由配置；实际值班表、号码、升级链和告警渠道全部为 **GATE**。以下为必须建立的值班基线，不是已经存在的生产值班。

### 2.1 值班层级

| 层级 | 角色 | 职责 | 响应目标 |
|---|---|---|---|
| L1 | Hypercare 值班工程师（DevOps/后端轮值） | 监控告警、初步分级、止血、拉群、记录时间线 | Sev1 立即；Sev2 15min 内确认 |
| L2 | 技术负责人 + 模块 owner（People/Time/Payroll/Platform） | 根因定位、发布/回滚建议、修复验证 | Sev1 15min 内加入；Sev2 30min 内 |
| L3 | 业务 owner（HR/财务/安全/法务） | 业务影响、对账口径、付款/更正/通知决策 | Sev1 立即；Sev2 1h 内 |
| 决策组 | 交付经理 + 技术负责人 + 业务 owner；工资加财务 | 回滚/继续/降级决策 | 按事故需要 |

**值班要求（GATE）**：

- [ ] 90 天值班表、主备轮换、时区/节假日覆盖已发布。
- [ ] Sev1 7×24 可联系；Sev2 工作时段 15min 内响应，非工作时段有兜底。
- [ ] 升级链最多 2 跳到达决策组；联系人、电话、备份联系人已验证。
- [ ] 告警路由到值班人并有测试告警；测试结果留证，不能只配置未验证。
- [ ] 交接班记录包含未关闭事件、风险、计划变更和工资/关账节点。
- [ ] 值班人有权停止发布/付款/切换（至少有权立即升级并冻结），权限边界书面化。

### 2.2 事件处理流程

```text
告警/用户报告
  -> L1 15min 内确认、建事件单、分级（不确定则升级）
  -> 止血：停止发布/付款/切换；必要时按 rollback.md 停写/回滚
  -> 通知：IC、技术、业务、财务/安全（按影响）
  -> 证据：时间线、request_id、日志、审计、对账输出、命令 exit code
  -> 修复/更正/回滚；双人复核高风险操作
  -> 验证：健康检查 + 对账 + 用户 smoke + 审计
  -> 关闭：根因、行动项、owner、期限；Sev1/2 复盘
```

事件单最少字段：事件 ID、Sev、开始/发现/缓解时间（UTC）、影响范围、当前系统状态（新/旧/只读）、已执行动作、回滚点、证据链接、通知对象、下一步与 owner。**不得在事件单中粘贴员工 PII、工资明细、密钥或银行账号全文。**

### 2.3 发布冻结与变更

- Hypercare 期间变更必须走 CCB/变更单（S-03，**GATE**）；至少包含价值、风险、测试影响、回滚方案和验证证据。
- Sev1 未关闭或存在 Sev1 风险时，禁止非修复类发布；Sev2 未在 SLA 内关闭时不得进入下一波/发布。
- 工资付款、税务申报、批量导出、路由切换、数据库恢复必须双人复核。
- 变更失败率/回滚率按月统计；超过计划 12.1 阈值（失败率 <10%、回滚率 <5%）时暂停非必要变更并复盘。

## 3. 监控与告警基线

### 3.1 健康检查

```bash
# 生产域名由 GATE 提供；下面是路径语义示例
curl -fsS https://hrms.example.invalid/v1/health/live
curl -fsS https://hrms.example.invalid/v1/health/ready
curl -fsS https://hrms.example.invalid/v1/health
```

| 探针 | 语义 | 告警动作 |
|---|---|---|
| `/v1/health/live` | 只证明进程可响应；不访问 DB/cache/storage | 用于容器重启判断；不要因依赖慢误杀进程 |
| `/v1/health/ready` | DB、cache、storage 全部可用才 200 | 503 立即升级；检查 DB/Redis/S3/队列 |
| `/v1/health` | DB 失败 503；cache/storage 失败可 200 `degraded` | `degraded` 必须告警并定位，不能当作 ready 通过 |

实现与测试：`backend/app/Modules/Platform/Services/HealthService.php`、`backend/app/Modules/Platform/Http/Controllers/HealthController.php`、`ReadinessController.php`、`backend/tests/Feature/HealthProbeTest.php`。生产实际负载均衡探测配置为 **GATE**。

### 3.2 关键信号

| 信号 | 目标/阈值 | 来源/采集 | 频率 |
|---|---|---|---|
| 可用性 | ≥99.9% | 负载均衡/探针/请求日志 | 每日 |
| P95 延迟 | <500ms | `http.request` 结构化日志的 `duration_ms`（`RequestLogMiddleware`）或 APM | 每日 |
| 错误率 | <0.5% | 5xx/业务失败统计 | 每日 |
| Sev1 | 0 | 事件单 | 实时 |
| MTTA / MTTR | ≤15min / ≤4h（Sev1） | 事件时间线 | 实时 |
| 假勤账本差异 | 0 未解释 | `ledger:reconcile` | 每日 |
| 待办 >24h 比例 | <1% | 工作流/待办查询 | 每日 |
| 工资按时率 | 100% | 工资批次/财务记录 | 每月 |
| 工资重大错发 | 0 | 工资平行/财务对账/事件单 | 每月 |
| 员工月活 | ≥90% | 访问/登录统计（脱敏聚合） | 每月 |
| 自助请假比例 | ≥80% | 假勤来源统计 | 每月 |
| 工资条查看率 | ≥95% | 工资条访问统计（脱敏聚合） | 每月 |
| 每百员工工单下降 | 较上线首月 ≥30% | 工单系统 | 每月 |
| 变更失败率/回滚率 | <10% / <5% | 变更单/发布记录 | 每月 |

以上目标直接来自计划 12.1。本仓库没有生产 APM、日志平台或工单系统，实际采集、看板和告警阈值配置均为 **GATE**；这里不预填任何生产指标结果。

### 3.3 日志与隐私

- `RequestLogMiddleware` 记录 `request_id`、tenant/user、route、status、duration，不记录请求体、查询串或响应体；日志仍须经共享脱敏处理器。
- 不在告警、工单、聊天或截图中粘贴员工 PII、工资明细、银行账号、Cookie、密钥或完整 SQL 结果。
- 审计事件（`audit_events`）是只追加证据；不得为“清理告警”删除审计。
- 数据导出必须按 `export_enabled`/权限/字段白名单和水印执行；发现越权导出按 Sev1/Sev2 处理并保留证据。

## 4. 每日 / 每周 / 每月对账节奏

### 4.1 每日（H1 前 2 周每日；之后工作日每日）

```bash
cd backend
php artisan people:as-of-check --date="$(date -u +%F)"
php artisan ledger:reconcile --as-of="$(date -u +%F)" --tenant=1
php artisan payroll:reconciliation --period=YYYY-MM
php artisan retention:preview --all --tenant=1
cd ..
```

每日检查：

- [ ] `/v1/health/ready` 无持续 503；`degraded` 有工单和 owner。
- [ ] 错误率/P95/队列积压/失败任务在阈值内；异常有事件单。
- [ ] `people:as-of-check` 退出 0：无重叠主任职、无孤儿任职。
- [ ] `ledger:reconcile` 退出 0：期初 + 发生 = 期末，未解释差异 0。
- [ ] 工资/关账期间的 `payroll:reconciliation` 退出 0；已发布/已付款批次不可变。
- [ ] 待办 >24h 比例 <1%；异常审批/卡单有人跟进。
- [ ] 备份任务完成、校验和/异地复制正常；失败即建 Sev2（发布前为阻断）。
- [ ] 安全告警、登录失败、撤权、导出、break-glass 审计样本抽查无异常。

每日产出：一页“系统健康卡”（可用性、P95/错误率、Sev、账本差异、工资状态、待办、备份、工单趋势），交给 Hypercare 战会。样本格式不预填结果。

### 4.2 每周

- [ ] 人数/组织/合同按法人和组织维度复核；未来生效/离职边界抽查。
- [ ] 工资批次/更正链/银行税务导出状态；未付款/未回执清单。
- [ ] UAT/工单 Top 问题、重复工单、培训缺口；Sev3/4 owner 和日期。
- [ ] 变更单、发布、回滚/失败变更统计；是否触发变更冻结。
- [ ] 备份恢复抽检（至少验证备份可读/校验和；完整恢复演练按季度/发布前）。
- [ ] 权限/会话/导出抽检；break-glass 使用是否双人、30 分钟、告警（实现见 IAM 相关服务与测试）。

### 4.3 每月

- [ ] 计划 12.1 全部月指标：工资按时率 100%、重大错发 0、员工月活 ≥90%、自助请假 ≥80%、工资条查看率 ≥95%、工单下降 ≥30%、变更失败率 <10%、回滚率 <5%。
- [ ] 工资至少一个完整周期与旧系统/财务总账对账；更正批次、税务/银行回执闭环。
- [ ] 季度要求（按季度执行）：完整恢复演练（SQLite drill 可重复，生产 MySQL/PITR 必须真实环境；**GATE**）、访问复核、密钥轮换/证书检查（按组织基线）。
- [ ] 法务保全/保留期抽查：`retention:preview --all` 只读；删除必须审批，法务保全优先（**GATE**）。
- [ ] 30/60/90 天复盘输入：指标趋势、事件、技术债、培训、手册更新。

### 4.4 对账异常处理

| 异常 | 立即动作 | 关闭条件 |
|---|---|---|
| 人数/组织/合同差异 | 冻结相关写入或切换；HR 数据 owner 对账 | 差异 0 或书面解释 + owner 签字（**GATE**） |
| 假勤账本差异 | 停止关账/工资输入；保留账本分录 | `ledger:reconcile` 退出 0；冲正/调整可追溯 |
| 工资总额/净额差异 | 冻结付款/发布；财务对账；必要时更正批次 | `payroll:reconciliation` 通过；财务签字；不删除历史 |
| 迁移 source→target 差异 | 停止下一波；`migrate:reconcile` + 源/目标抽样 | 未解释差异 0；迁移 run 和映射可追溯 |
| 备份/恢复失败 | 暂停发布；检查备份/凭据/容量 | 真实恢复演练通过并留证（**GATE**） |
| 审计/导出/权限异常 | 按安全事件处理；撤销会话/链接；保留证据 | 安全确认 + 修复验证 + 复盘 |

## 5. 支持与用户沟通

- 支持渠道、服务时间、FAQ、培训材料、升级路径必须在上线前发布；具体渠道/负责人为 **GATE**。
- 工资条、假勤、合同等敏感问题只通过受权渠道处理，不在群聊公开个人信息。
- 用户报告的问题必须进入工单并分级；Sev1/2 不得只靠私聊解决。
- 每次工资发布/关账前后发布操作通知：时间窗口、只读/可写、支持入口、已知问题。
- 已发通知/Offer/绩效确认不可回滚；客服话术必须说明更正/撤回流程，不能承诺“删除历史”。

**不允许退出的情况**：任一 Sev1 未关闭、Sev2 超 SLA、工资/假勤/人数/合同有未解释差异、真实备份恢复/PITR 演练未通过、关键用户未培训、发起人未批准。到期不是退出理由；应延长 Hypercare 并明确新的退出日期（**GATE**）。
