# ADR-0026: 页面覆盖注册表与验收口径

- **状态：** Accepted — 2026-11-25
- **决策：** C8（页面范围）
- **关联：** `docs/audit/2026-11-25-v11-page-inventory.md`、`docs/audit/2026-11-25-v11-page-access-blueprint.md`
- **复审触发：** V1.1 03A/03B 页面清单变化、页面合并/删除、新增平台模块

## 背景

V1.1 要求 17 个截图菜单、140 个业务页、14 个平台模块、26 个工作包。当前前端
只有 20 条路由记录、18 个视图、12 个导航项；约 123 个页面完全缺失。此前的
“README 声明 + mock E2E”无法证明页面覆盖，删除页面也不会让测试失败。

用户确认：需要明确实现的功能和页面，并允许破坏性重构。因此需要一个机器可核对
的页面注册表，作为菜单、路由、权限、API、测试、E2E 的单一事实源。

## 决定

1. **页面注册表是唯一覆盖清单。**
   - 路径：`frontend/src/router/registry.ts`
   - 条目：`path/name/component/capability/menu/group/requiredApis/states/e2e`
   - 数量：140 个业务页 + 14 个平台模块入口 + 6 个基础页 = **160 条**。
2. **页面清单由脚本从 V1.1 源文档生成**，不手工维护计数。
   - 生成器：`scripts/docs/generate_v11_inventory.py`
   - 输出：`docs/audit/2026-11-25-v11-page-inventory.md`
   - CI 校验：生成结果与仓库文件 diff 必须为空。
3. **CI 覆盖门禁**：
   - `PAGE_REGISTRY` 数量 = 160；路径唯一。
   - 每个条目有真实组件文件；不存在则标记 `missing` 并失败。
   - 每个条目至少有 1 个角色模板映射（角色-页面矩阵）。
   - 每个条目至少有 1 条真实栈 E2E；mock E2E 不计入。
   - 每个页面有 loading/empty/error/forbidden/partial 五态；缺态失败。
   - 每个页面有至少 4 类权限负测；缺类失败。
4. **菜单与路由同源**：菜单树来自 `/v1/me/permissions` + 注册表交集；不再维护第二份
   静态导航数组。父菜单授权不等于子页面授权。
5. **动态组件白名单**：后端返回的 `component_key` 只能映射到注册表已声明的组件；
   不允许任意 `import()` 路径。
6. **页面交付定义**：真实 API、OpenAPI schema、运行时校验、权限、五态、组件测试、
   真实 E2E、审计。缺一不算完成。

## 备选方案

| 方案 | 拒绝原因 |
|---|---|
| 手工维护菜单数组 | 会与路由/权限漂移；删除页面测试仍绿 |
| 只按截图 17 个一级菜单验收 | 140 个子页仍有 123 个缺失 |
| 以 mock E2E 作为覆盖证明 | mock 形状与真实后端不同；无法发现契约漂移 |
| 后端动态返回完整组件路径 | 代码注入风险；前端无法类型检查 |

## 后果

- 新增页面必须同时改：注册表、组件、API、OpenAPI、权限、角色矩阵、测试、E2E。
- 删除页面必须同步删除注册表条目并更新角色矩阵；否则 CI 失败。
- `docs/audit/2026-11-25-v11-page-inventory.md` 成为可引用的页面事实源。
- 页面数量从“口头承诺”变为“CI 可计算”。

## 验证

- `routeRegistry.spec.ts`：160 条、路径唯一、能力非空。
- `audit_route_coverage.mjs`：与 V1.1 清单 diff 为空。
- `PagePermissionCoverageTest`：每个页面能力码存在。
- `pageAccessMatrix.spec.ts`：每个页面至少一个角色映射。
- 真实栈：160 条注册表巡检 0 错误边界、0 非预期 401/403/404。

## 复审触发

- V1.1 清单变化（新增/合并/删除页面）。
- 平台模块新增或合并。
- 页面注册表条目 > 200，需要分组/懒加载策略。
- 真实栈 E2E 时长超过 30 分钟，需要并行/分片。
