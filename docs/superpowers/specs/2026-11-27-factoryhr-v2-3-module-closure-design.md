## 1. 结论

当前系统并非“页面数量不足”，而是“页面、动作、契约、权限、证据”没有形成一条可执行链路。V2.1 最终验收已明确记录：

- 155 个页面中 123 个仍经共享壳渲染；
- `PlatformWorkspace.vue` 达 4583 行、含 32 个 `mode` 分支；
- 52 条真实栈 Playwright 仅完成收集，未完成执行；
- 五角色真实栈 UAT 未执行；
- 生产决策为 **NO-GO**。

V2.3 截图进一步暴露了同一根因：旧壳直接把技术 code、单位、不可用原因和 ADR 文案渲染给业务用户；部分配置页只有“表头 + 空表”，后端也没有对应的写命令。因而整改不能停留在 CSS、中文映射或补按钮，必须完成：

1. 删除旧壳与旧入口，而不是继续兼容；
2. 为每个保留页面补齐真实读契约和真实写命令；
3. 把页面、动作、API、能力、数据范围、字段策略、测试证据绑定成单一链路；
4. 用真实数据库、真实账号与真实浏览器证明闭环。

## 2. 目标与非目标

### 2.1 目标

1. **21 个模块各自形成可独立验收的业务闭环**，模块内不再出现“有菜单、无可执行功能”的页面。
2. **主工作区收敛**：一个业务对象只有一个主入口；详情是稳定深链；新增、编辑、审批、归档、导出是工作区或详情页的动作。
3. **旧入口彻底删除**：本次裁决不做旧 URL 兼容、不做重定向、不做隐藏菜单；被删入口的能力必须迁入保留页面并在矩阵登记。
4. **读写对称**：每个列表至少一个真实读 API；每个写动作对应一个真实写 API、一个 capability 和一个负向权限测试。
5. **中文业务界面**：不显示英文枚举、单位码、API 路径、ADR 编号、异常堆栈或技术不可用原因。
6. **可证明交付**：模块退出必须附真实测试日志、浏览器截图、数据库前后快照和未完成项清单。

### 2.2 非目标

- 不恢复多租户、多法人、SaaS 运营、跨公司账务。
- 不重写已通过验收的工资计算内核、审批效果内核、人员任职事实内核。
- 不为旧 URL、旧页面码或旧共享壳建设兼容层。
- 不把未接入的真实第三方（税务、银行、门禁、电子签）伪装成已完成集成。
- 不以静态映射、单元测试或文档声明替代浏览器与数据库验收。

## 4. 旧入口删除规则

### 4.1 删除定义

“彻底删除”必须同时满足：

1. 从 `frontend/src/router/registry.ts` 移除页面条目；
2. 从 `frontend/src/router/pageComponents.ts` 与各模块 `pages/index.ts` 移除组件映射；
3. 删除对应页面组件、旧 config、旧定义与仅为其服务的测试；
4. 从 `backend/routes/api.php` 删除仅为该入口存在、且没有其他合法消费者的路由；
5. 从 OpenAPI 删除对应 operation；
6. 从 capability catalog、动作清单与角色种子移除孤儿能力；
7. 在映射矩阵中登记能力去向；
8. 执行 `rg` 证明无残留引用。

### 4.2 禁止事项

- 不保留旧 URL 重定向；
- 不保留仅为旧路径服务的兼容组件；
- 不保留“已隐藏但仍可直接访问”的调试页面；
- 不以删除页面代替迁移功能；
- 不在未登记能力去向时删除入口。

### 4.3 允许保留的共用组件

`DataTable`、`PageShell`、`MetricCard`、`FormDrawer`、`DetailTabs` 等无业务分支的共享组件可保留；`PlatformWorkspace`、`PeopleWorkspace`、`TimePayrollPage`、`TalentWorkspacePage` 等带 `mode`/config 业务分支的旧壳必须在对应模块任务中删除。

## 5. 页面与动作契约

### 5.1 每个保留页面的最低要求

| 维度 | 要求 |
|---|---|
| 身份 | 唯一 `page_code`、唯一路由、唯一组件 |
| 读 | 至少一个真实读 API；声明分页、筛选、排序与 as-of |
| 动作 | 每个写动作有 `actionKey`、中文名、capability、HTTP 操作、确认策略 |
| 状态 | loading / empty / unconfigured / forbidden / error / success 六态 |
| 权限 | 服务端 capability + anchor + field profile 同时生效 |
| 中文 | 所有枚举、单位、状态、错误、空态均经领域字典 |
| 证据 | 单元、契约、权限负测、浏览器 E2E 各至少一条 |
| 回退 | 可独立提交、可回滚；删除型任务附数据快照 |

### 5.2 动作与 API 对称校验

新增门禁 `scripts/audit-v23-module-closure.mjs` 必须验证：

1. 保留页面在 `PAGE_REGISTRY` 中恰有一条；
2. 每个 `requiredApis` 操作存在于 OpenAPI，且 capability 一致；
3. 每个写操作至少被一个页面动作引用；
4. 每个页面动作至少被一个 Playwright 用例覆盖；
5. 被删除页面不在 registry、pageComponents、pages barrel、Vue 文件、测试快照或 OpenAPI 中残留；
6. 每个矩阵行的目标页面存在，且其能力覆盖原入口能力；
7. 每个模块至少一条跨域 E2E。

### 5.3 六张截图页面的目标契约

| 页面 | 目标 | 后端事实 |
|---|---|---|
| 部门人数分析 | 合并到 `/dashboard` 的“部门人数”分区；中文指标、单位、口径；可下钻 | `GET /v1/reporting/dashboard` 与指标查询 |
| 假期规则 | 合并到 `/leave?tab=policies`；规则版本可新增、停用、查看历史 | 新增 `POST /v1/time/leave/policies`、`POST /v1/time/leave/policies/{id}/retire`，需迁移与 OpenAPI |
| 薪资项目 | 合并到 `/payroll?tab=components`；项目版本可新增、复制新版本、停用 | 在现有 `GET/POST /v1/payroll/items` 上新增版本与停用命令 |
| 角色管理 | 保留 `/system/roles`；四 Tab 中文；去 ADR/技术码；内置角色可复制 | 现有角色授权接口，补页面目录独立页与原子保存测试 |
| 社保公积金参数 | 唯一入口 `/benefits`；旧 `/payroll/statutory` 删除 | 统一 `statutory_parameters` 为参数主源，福利方案不复制参数 |
| 岗位任职资格 | 合并到 `/hr/positions?tab=requirements`；岗位详情内追加版本 | 现有 `GET/POST /v1/positions/{id}/requirements`，补详情与版本历史契约 |

## 6. 后端整改原则

### 6.1 唯一写入者

沿用 V2.3 的所有权表：

| 事实 | 唯一写入者 |
|---|---|
| Person / Employment / Assignment / Terms | People |
| 部门 / 岗位 / 编制 | Organization |
| 入转调离单据与生效结果 | Lifecycle |
| 假期类型、规则、余额流水 | Time/Leave |
| 考勤、加班、出差 | Time |
| 工资项目、方案、批次、工资条 | Payroll |
| 社保参数、福利方案、参保 | Payroll/Benefits |
| 招聘、绩效、培训 | Talent |
| 公告与通知 | Engagement |
| 角色、页面、动作、范围、字段 | IAM |
| 审批实例与待办 | Workflow |
| 报表定义与导出 | Reporting |

### 6.2 写命令要求

每个新增或修改写命令必须：

- 使用现有 `CommandRunner` / 幂等键 / 审计模式；
- 在同一数据库事务内完成聚合一写入与审计；
- 对状态机非法迁移返回稳定 409；
- 对越权返回 403，不泄露对象是否存在；
- 同步更新 OpenAPI、capability catalog、动作清单与测试；
- 涉及金额时只用整数最小单位与十进制定点字符串；
- 涉及日期时按公司时区与共享日历计算。

### 6.3 前向迁移

- 禁止修改已合并迁移；
- 新增列、表、索引必须使用匿名类迁移；
- 删除列或表必须先做使用面扫描、备份、测试库演练、恢复校验；
- 每个破坏性迁移任务必须在计划中列出回退点与数据快照命令。

## 7. 测试与验收

### 7.1 模块级门禁

每个模块完成时必须同时具备：

1. 后端 feature 测试：成功路径、校验失败、越权、状态冲突、幂等；
2. 契约测试：OpenAPI operation、capability、错误码；
3. 前端单元测试：六态、动作可见性、中文映射、表单校验；
4. 浏览器 E2E：真实登录、真实数据、刷新持久、撤销权限后拒绝；
5. 静态门禁：`pnpm gate:all`；
6. 证据：命令、退出码、日志、截图、数据前后快照。

### 7.2 跨模块 E2E

V2.3 的 12 条跨域场景必须全部有可执行 Playwright 用例，不允许只收集：

- E2E-01 招聘转入职
- E2E-02 请假到薪资
- E2E-03 HR 代请假
- E2E-04 组织迁移影响权限与报表
- E2E-05 调薪到工资条
- E2E-06 加班到调休或计薪
- E2E-07 出差到考勤与费用
- E2E-08 绩效发布与申诉
- E2E-09 培训到员工档案
- E2E-10 角色授权到 API/导出
- E2E-11 合同到期与续签
- E2E-12 公告受众与回执

### 7.3 生产判定

只有在以下全部满足后才可给 GO：

- 26 个主工作区全部通过模块退出；
- 120 个被删入口全部有映射与残留扫描证据；
- 12 条跨域 E2E 全部真实执行通过；
- 五角色真实栈 UAT 通过；
- 备份恢复与回滚演练通过；
- 无 Critical/Important 未关闭评审项。

## 8. 风险与控制

| 风险 | 控制 |
|---|---|
| 删除入口导致功能丢失 | 矩阵逐条目标映射；删除前能力覆盖校验；先迁移后删除 |
| 新增写命令绕过既有状态机 | 复用 CommandRunner、幂等键、审计与领域服务 |
| 收敛后页面变成巨型 Tab | Tab 必须同对象、同任务、同范围；跨对象回主工作区 |
| 中文映射掩盖金额单位错误 | 金额统一格式化函数；后端整数分；E2E 断言金额 |
| 权限只在前端隐藏 | 每个动作配 403 负测；撤销权限后旧标签页再次提交必须失败 |
| 迁移损坏历史数据 | 前向迁移、备份、演练、恢复校验、双人评审 |
| 计划再次停留在文档 | 每模块固定证据目录与退出检查；未执行标 NOT RUN |

本规格需用户确认以下四项后才能进入计划执行：

1. 26 个侧栏主工作区与 7 个详情深链的目标结构；
2. 不再保留旧 URL 兼容，120 个旧入口彻底删除；
3. 六张截图页面的目标归属与新增写命令范围；
4. 模块退出必须包含真实数据库与浏览器证据，不以静态门禁代替。

确认后按 `docs/superpowers/plans/2026-11-27-v2-3-remediation-master-plan.md` 的模块顺序执行。
