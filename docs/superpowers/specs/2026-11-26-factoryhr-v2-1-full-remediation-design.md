## 1. 结论

当前系统的问题不是若干页面样式缺陷，而是四类“声明存在、业务未闭环”的结构性偏差：

| 偏差 | 当前证据 | 业务后果 |
|---|---|---|
| 页面数量代替任务闭环 | 注册表 160 条，158 条 `actions: []`；People 域 39 个页面共享 `PeopleWorkspace` | 有页面、有路由、有门禁，但用户仍要在多个入口之间拼任务 |
| 权限元数据代替真实授权 | 后端 `PermissionResourceCatalog.actions` 含能力码，前端注册表动作却为空；系统页只声明 `GET /me/permissions` | 角色页无法可靠展示“某页真实可分配按钮”，按钮/API/能力可能漂移 |
| 多公司概念残留 | 约 401 个运行文件命中 `tenant_id`/`legal_entity_id`/`LEGAL_ENTITY`；路由仍有法人上下文；前端仍有法人编号输入 | 单公司模型未收敛，权限范围、唯一索引、表单和报表口径冲突 |
| 文档与运行姿态冲突 | ADR-0018 已接受密码登录；ADR-0025 仍写“内网生产默认开启 MFA”；V1.1 多处要求强制 MFA/租户 | 开发代理会按不同文档重新引入已裁决禁止的能力 |

**总根因：**

> 系统缺少一条从“用户任务”到“页面、按钮、能力、API、数据范围、字段策略、测试证据”的双向可验证链路。各处分别维护字符串清单，门禁只验证清单存在，无法证明真实业务闭环。

因此整改必须同时完成四件事：统一规范与裁决、统一权限和契约真相源、以员工为样板完成纵向闭环、再按业务域推广并用真实栈验收。

## 2. 目标与不变量

### 2.1 业务目标

1. **权限可操作、可验证**：管理员能在系统内完成用户、角色、页面、按钮、数据范围、字段权限配置；服务端对每条越权请求给出稳定拒绝。
2. **单公司语义彻底收敛**：全实例只服务一家公司；保留部门、岗位、组织树与数据范围；不再出现租户、法人、公司切换。
3. **密码登录成为唯一主流程**：账号密码单步登录；不强制 MFA、验证码、SSO；认证简化不等于授权简化。
4. **页面按用户任务组织**：主工作区进侧栏；详情为可分享深链接；新增/编辑/归档为页面动作；页面内 Tab 只服务同一对象、同一任务、同一数据范围。
5. **所有业务域真实闭环**：V1.1 的 140 个业务能力点、14 个平台条目不能因页面收敛而消失；每个能力必须落到可操作界面、真实 API、权限与测试。
6. **生产级展示**：普通用户界面不出现英文枚举、接口路径、表名、字段档位、开发缺口或演示说明。
7. **可证明交付**：静态门禁、单元/集成/E2E、真实栈、迁移演练、性能与备份恢复全部有实际输出，未执行不得声称通过。

### 2.2 不可破坏的架构不变量

- 每一张表只有一个写入模块；跨模块只能通过 `Contracts`、只读投影或事件。
- 每个 `/v1` 路由必须有 capability 守卫，公开白名单仅限健康、元数据与登录等明确条目。
- 页面进入权由 `role_pages` 与能力共同决定；动作执行权由能力授权决定；不得用页面读权限推导写权限。
- 动作授权必须成对携带数据范围与字段策略；不得把不同角色的动作与范围自由拼接。
- 金额使用整数最小货币单位；费率使用至少 1e6 缩放的十进制字符串；PHP 不得使用浮点金额。
- 时间 UTC 存储；业务日期按 `company_profile.timezone` 与共享日历计算。
- 迁移 forward-only；不得修改已合并迁移；破坏性迁移必须先备份、测试库演练和恢复校验。
- 测试与种子只使用合成数据；不得提交 `.env`、真实凭据、数据库文件或真实员工信息。
- OpenAPI 3.1 是 API 契约唯一真相源；路由、能力、前端类型和测试必须同步。

### 2.3 本规格明确非目标

- 不建设 SaaS 注册、租户套餐、跨租户管理、多公司切换、集团合并报表。
- 不建设强制 MFA、短信/邮件验证码、SSO/LDAP/OIDC/WebAuthn 作为上线前置。
- 不为尚未上线的旧 URL 或旧页面码建设永久兼容层。
- 不重写 Person/Employment/Assignment/Terms 事实内核，不把工资、考勤、审批算法改成新口径。
- 不追求“每个字段一个页面”，也不把复杂长流程强行塞进小弹窗。

## 3. 目标架构

### 3.1 五层单一链路

```text
用户任务（Task）
  → 页面（Page：workspace / detail / governance / base）
    → 页面动作（ActionSpec：新建/编辑/归档/审批/导入/导出/发放）
      → 能力（Capability：语义 + anchor 类型 + 最高字段档位）
        → API 操作（OpenAPI operation + x-capability + 服务端能力守卫）
          → 数据范围（SELF/MANAGED/ORG_UNIT/ORG_SUBTREE/COMPANY/CASE/PAYROLL_RUN）
          → 字段策略（P0–P3）与审计
```

**规则：**

- 一个页面是“完成一个主要任务的工作区”，不是字段分组、弹窗或单一步骤。
- 一个动作必须有唯一 `actionKey`、一个能力码、一个真实 OpenAPI 操作、一个 UI 形态与确认策略。
- 页面可以没有写动作；一旦声明写 API，就必须声明对应动作，反向也必须成立。
- 详情页不进入侧栏，但必须有稳定 URL、页面权限与字段遮罩。
- 页面内 Tab 合法的判定：同一业务对象、同一用户任务、同一数据范围。跨对象切换必须回到侧栏。

### 3.2 页面分类

| 类型 | 定义 | 示例 | 菜单 |
|---|---|---|---|
| `workspace` | 列表/看板为主工作区，承载查询与常规动作 | 员工列表、部门工作台、薪资工作台 | 是 |
| `detail` | 单个业务对象上下文，支持深链与区域页签 | 员工详情、异动案例详情、合同详情 | 否 |
| `governance` | 配置/治理工作台，操作影响全局规则 | 角色权限、菜单/页面、字段策略 | 是 |
| `base` | 登录、403、404、会话等基础页 | `/login`、`/forbidden` | 否 |

原有 160 条条目必须逐条映射到上述类型；被合并的条目记录为“动作/视图/长流程”，不得直接删除功能。

### 3.3 前端结构

```text
frontend/src/
  shared/
    ui/            PageShell, DataTable, FormDialog, FormDrawer, DetailTabs, ActionGate
    display/       中文领域字典、金额/日期/状态 formatter、未知码遥测
    permissions/   页面/动作投影、路由守卫、按钮判定
  modules/
    people/{employees,organization,lifecycle,contracts}/
    time/{attendance,leave,overtime,travel}/
    payroll/
    talent/{recruiting,performance,training}/
    engagement/{notices,notifications}/
    reporting/
    platform/{iam,workflow,settings,audit}/
  router/
    registry.ts        页面资源，不承载业务分支
    navigation.ts      只从注册表派生主菜单
    pageComponents.ts  页面组件映射
```

**约束：**

- `shared/ui` 不得出现 `if (module === 'payroll')` 一类业务分支。
- 每个页面文件只服务一个页面身份；不得通过“传入不同 config”让 39 个页面共享一个巨型业务组件。
- 巨型共享壳（`PeopleWorkspace`、`TalentWorkspacePage`、`PlatformWorkspace`）按纵向任务拆解，不得先全局移动文件再补功能。

### 3.4 后端结构

- 保留 Laravel 模块化单体与现有模块所有权。
- 员工多实体写入新增应用命令（例如 `POST /v1/employees/onboard`）：同一数据库内事务全提交/全回滚；幂等键防重复；提交后副作用走 Outbox。
- 读模型只返回经授权的字段与稳定分页结构；不得把未授权字段交给前端“遮罩”。
- 权限判定继续使用 `Capability × Anchor × FieldProfile` 内核；新增 `COMPANY` 锚点替代 `LEGAL_ENTITY`。
- 角色授权变更在同一事务内写入页面、能力、范围与字段策略，并重放受影响用户快照、递增会话版本。

### 3.5 单公司模型

```text
FactoryHR 单实例
└── company_profile（唯一公司：名称、国家、时区、币种、日历策略）
    ├── 组织树 / 部门 / 岗位
    ├── 员工 / 雇佣 / 任职 / 条款 / 合同
    ├── 考勤 / 假勤 / 薪资 / 绩效 / 招聘 / 培训
    └── 用户 / 角色 / 页面 / 按钮 / 数据范围 / 字段权限
```

- `company_profile` 是配置单例，不是数据隔离边界。
- 删除 `tenant_id`、`legal_entities`、`legal_entity_id`、`X-Legal-Entity-Id`、`activeLegalEntityId`、`tenantLabel` 及对应模型/契约/中间件。
- 唯一索引改为单公司等价约束（如 `code`、`(code, version)`），不得留下依赖旧列的隐式唯一性。
- 原 `LEGAL_ENTITY` 授权绑定迁移为 `COMPANY`：`anchor_id=null`、`anchor_key=0`。
- 跨法人负测替换为跨部门、越本人、越审批案例、越工资批次负测。

### 3.6 登录与安全姿态

**登录流程：** `/login` → 账号 + 密码 → 服务端会话 → `/me/permissions` → 仪表盘或首个有权页面。

**保留：**

- Laravel 标准密码哈希与验证。
- 登录限流、连续失败锁定、管理员重置密码。
- HttpOnly、SameSite 会话 Cookie；按真实协议配置 Secure；写请求 CSRF。
- 账号禁用、密码修改、角色撤销后的会话失效或下一次请求拒绝。
- 登录、失败、权限变更、敏感读取/导出审计。
- 内网网段限制与防火墙禁止公网入口（部署验收项）。

**关闭/非阻塞：**

- 默认 `IAM_MFA_ENABLED=false`；MFA、WebAuthn 代码可保留，但不出现在主登录 UI，不作为任何角色或 API 的验收前提。
- 当开关关闭时，`mfa.enrolled` 与 `mfa.step-up` 必须放行，且不得绕过 capability 守卫。
- 删除图形验证码、短信/邮件验证码、SSO/LDAP/OIDC 作为登录前置的产品要求。

## 4. 关键设计决策

### D1 页面收敛，但能力不减

160 条注册项作为追踪清单保留在文档中；最终页面码按任务型模型收敛。每条旧条目必须有“保留 / 合并为动作 / 合并为视图 / 合并为长流程 / 明确废弃”结论与能力归属。只有用户签认的“明确废弃”才可删除能力。

### D2 前端不复制后端权限目录

动作清单由后端能力目录与 OpenAPI 生成机器可读 JSON；前端构建时消费该产物。运行时不读文档，不维护第二套 `actions` 手写清单。CI 双向校验页面、动作、能力与 API。

### D3 员工新增改为服务端原子命令

浏览器不得连续创建 Person → Employment → Assignment → Terms。新命令必须一次提交全部事实、事务回滚、幂等重试、审计与权限校验；旧低层 API 可保留给受控后台任务，但不得作为员工前台主路径。

### D4 不做上线前兼容双轨

系统尚未上线，旧 URL 不做永久重定向，旧页面码不做并集过渡。迁移脚本可以一次性重写角色页面授权与书签，但必须在测试库演练并输出差异报告。

### D5 单公司 cutover 纳入本次交付

代码、OpenAPI、种子、测试、部署脚本与数据库迁移在同一整改范围内完成；生产执行仍需独立窗口与备份审批。不得只改代码而留下旧列，也不得直接删列而不先合并历史数据。

### D6 MFA 非阻塞、能力可保留

ADR-0018 保持有效；修订 ADR-0025 的默认开启措辞。MFA 开关关闭时所有合法密码登录路径与授权 API 必须通过；安全补偿依赖网络边界、限流、会话撤销、最小权限与审计。

### D7 展示契约前置

先建立页面骨架、表格、表单、详情、动作按钮与中文字典，再改业务页。不得每页自建一套表格/表单/文案。

### D8 门禁从存在性升级为行为

新增门禁必须能对以下反例失败：写按钮无动作声明、动作无 API、API 无能力、页面出现跨模块 Tab、英文枚举、技术文案、裸控件、权限只藏按钮而后端放行、导出绕过字段/范围。

## 7. 权限与数据设计细节

### 7.1 页面与动作

- `PageSpec` 增加 `kind`、`primaryObject`、`detailOf`；保留现有 `path/name/componentKey/capability/menu/layer/wave/requiredApis/states/e2e/negativeTests`。
- 动作不再手写在前端注册表；构建时从 `docs/generated/page-actions.json` 注入。
- `ActionSpec` 必填：`key`、`pageCode`、`label`、`capability`、`api`、`ui`、`confirm`、`anchorTypes`、`fieldProfileMax`。
- 后端 `PermissionResourceCatalog` 的 `actions` 与 OpenAPI `x-capability` 必须一致；不一致时 CI 失败。

### 7.2 授权求值

对一次请求：

```text
认证会话有效
∧ 页面可见（role_pages ∩ 页面所需能力）
∧ 动作能力已授予
∧ 授权绑定有效且 anchor 覆盖目标对象
∧ 字段档位允许读取/写入
∧ 业务状态允许该动作
∧ 未命中 SoD 禁止规则
→ 允许；否则返回稳定错误码
```

- 拒绝统一使用 401/403/404/409/422 之一，不因“资源存在但无权”泄露存在性（按安全策略选 403 或 404）。
- 角色授权变更后重放权限快照；旧标签页、缓存、导出任务下一次请求必须重新求值。
- 至少保留一个可用系统管理员；普通管理员不得自授超级管理员或超出自身可授予范围的角色。

### 7.3 数据范围

| 范围 | 语义 |
|---|---|
| `SELF` | 本人任职/本人数据 |
| `MANAGED` | 下属任职 |
| `ORG_UNIT` | 指定部门 |
| `ORG_SUBTREE` | 指定部门及子部门 |
| `COMPANY` | 本实例全公司数据，非多公司切换 |
| `CASE` | 指定审批案例 |
| `PAYROLL_RUN` | 指定工资批次 |

部门范围通过组织树选择；不出现租户/法人选择器。高敏感范围需要普通二次确认，不是 MFA。

### 7.4 字段策略

- P0 公开、P1 内部、P2 敏感、P3 严格受限。
- 字段可见/可编辑/可导出由服务端裁剪；前端遮罩只用于展示，不作为安全边界。
- 导出、附件下载、统计与搜索参数同样受范围和字段策略约束。

## 8. 单公司迁移设计

### 8.1 迁移前盘点

必须生成并人工核对：

- 所有含 `tenant_id`、`legal_entity_id` 的表、索引、外键、唯一约束。
- 每个表的行数、空值、重复键与跨法人同键冲突。
- 授权绑定中 `LEGAL_ENTITY` 记录及目标 `COMPANY` 映射。
- 工资、合同、请假、审计等历史数据保留策略。
- 前端、OpenAPI、种子、部署脚本与测试中的旧概念引用清单。

### 8.2 迁移顺序

```text
1. 创建/校验 company_profile 单例，明确保留公司的名称、时区、币种、日历
2. 新增 COMPANY 锚点；把 LEGAL_ENTITY 绑定迁移为 COMPANY
3. 合并重复业务键，重建不含 tenant/legal_entity 的唯一索引
4. 代码切换到 COMPANY 与 company_profile 上下文
5. 删除 X-Legal-Entity-Id、tenant_id、legal_entity_id 列与 legal_entities 表
6. 删除旧模型、Contracts、中间件、前端状态与表单字段
7. 全量测试、迁移演练、备份恢复、真实栈验收
```

**禁令：**

- 不在同一个 PR 中夹带 CSS/菜单重构与删列迁移。
- 不在未备份、未演练的情况下执行生产删列。
- 不通过放宽扫描测试、保留隐藏列或“只改前端文案”宣称单公司完成。

### 8.3 数据冲突处理

- 若存在多个法人/租户的业务键冲突，迁移必须失败并输出冲突清单，人工裁定，不得静默合并。
- 历史工资、合同、请假、审计数据必须保留可追溯的公司归属证据；无法判定时停止并上报。
- 回滚以数据库快照恢复为主；迁移后代码回滚不得依赖已删除列。

## 9. 页面与展示设计

### 9.1 页面骨架

所有业务页使用统一骨架：

- 页头：标题、上下文、主操作、面包屑（详情页）。
- 筛选区：可折叠、可重置、保持分页与查询条件。
- 内容区：`DataTable` 或详情分区；加载、空、错误、无权、部分失败五态。
- 动作区：主操作在页头，行操作在表格；危险动作二次确认。
- 反馈：成功/失败使用统一消息与 `traceId`，不向业务用户暴露 JSON/SQL/HTTP。

### 9.2 表格与表单

- 表格统一使用 Element Plus `ElTable`/分页/空态；不得在业务页散落裸 `table`。
- 常规创建/编辑使用 `ElDialog`；复杂多段建档使用 `ElDrawer` 或分步抽屉；不得为动作注册页面。
- 表单校验：必填、长度、格式、服务端错误归位；提交中禁重入；关闭未保存需确认。
- 金额显示币种与小数位；时间显示公司时区；未知枚举显示“未知”并记录开发告警。

### 9.3 文案分层

| 层 | 内容 | 面向 |
|---|---|---|
| 用户文案 | 业务术语、操作结果、可修复错误 | 普通用户 |
| 运维信息 | traceId、错误码、审计记录 | 管理员/运维 |
| 开发信息 | 接口路径、表名、能力码、字段档位 | 仅开发文档/技术详情，默认不显示 |

主界面禁止出现：`GET /v1/...`、表名、`Wave`、`TODO`、`MINOR_UNITS`、`ACTIVE`、`FULL_TIME`、字段档位、演示/缺口说明。

## 10. 测试与门禁设计

### 10.1 新增/重写门禁

| 门禁 | 必须失败的反例 |
|---|---|
| `actions:check` | 写 API 无动作；动作无 API；动作能力与 OpenAPI 不一致；未知能力 |
| `page-model:check` | 创建/归档注册为页面；详情有菜单；页面内跨模块导航 |
| `ui-primitives:check` | 业务页裸 table/input/select；无统一五态；危险动作无确认 |
| `copy:check` | 用户界面出现英文枚举、接口路径、表名、字段档位、演示文案 |
| `task-closures:check` | 列表无法完成本对象创建/查看/编辑/归档；详情无入口 |
| `authorization:negative` | 藏按钮但 API 放行；跨部门/越本人/字段越权成功；撤权后旧会话仍可用 |
| `single-company:check` | 运行路径仍引用 tenant/legal entity；旧锚点或切换器存在 |
| `migration:rehearsal` | 迁移不可重复、备份不可恢复、冲突数据静默合并 |

### 10.2 测试层级

- **单元**：授权求值、字段裁剪、金额/日期格式化、状态机、迁移映射函数。
- **组件**：页面五态、动作可见性、表单校验、弹窗焦点与关闭确认。
- **API 集成**：401/403/404/409/422、幂等、事务回滚、范围与字段拒绝。
- **E2E**：五类真实角色（系统管理员、人事管理员、部门经理、普通员工、工资专员）从登录到任务完成。
- **真实栈**：MySQL、Redis、队列、备份恢复、迁移演练、性能基线。
- **人工 UAT**：17 个菜单入口、关键任务闭环、文案与无障碍。

### 10.3 证据规则

- 每个任务必须记录命令、退出码与关键输出；未执行的检查标注 `NOT RUN`。
- 静态映射通过不得替代行为验收。
- 真实栈未通过时不得声称生产就绪。
- 迁移演练必须包含“迁移前快照 → 迁移 → 校验 → 恢复 → 再校验”的完整证据。

## 11. 验收标准

### 11.1 业务验收

1. 系统管理员、人事管理员、部门经理、普通员工、工资专员五类账号均可仅凭密码登录。
2. 每个角色从登录 → 菜单 → 页面 → 按钮 → 数据 → 字段 → 导出形成完整闭环。
3. 员工列表可完成查询、新建、查看详情、编辑、归档/恢复；详情可维护任职、条款、经历、联系人、证照、附件与变更。
4. 员工新增失败注入时无部分 Person/Employment/Assignment/Terms 残留；重复幂等键不重复建档。
5. 部门、岗位、异动、合同、考勤、假勤、加班、出差、薪资、绩效、招聘、培训、报表、公告均有真实读写闭环。
6. 普通用户界面无英文枚举、接口路径、表名、字段档位或开发说明。

### 11.2 权限验收

1. 无页面权限不能通过 URL 进入；有页面无动作时按钮不可见且 API 403。
2. 跨部门、越本人、越审批案例、越工资批次请求被拒绝。
3. 字段越权被服务端裁剪；导出不能绕开范围与字段策略。
4. 撤权、停用账号后旧会话/旧标签页下一次请求失效。
5. 角色保存并发冲突不能覆盖他人修改；普通管理员不能自授超管。
6. 至少保留一个可用系统管理员。

### 11.3 单公司验收

1. 运行代码、OpenAPI、种子、部署脚本中旧概念零引用（迁移文件仅允许删除旧列的语句）。
2. 测试库 `migrate:fresh --seed` 成功；历史数据迁移演练通过。
3. 删除列后备份可恢复，关键表行数与校验和一致。
4. 唯一索引与业务键在单公司模型下正确；无跨法人同键冲突残留。
5. 工资、合同、请假、审计历史可追溯，无丢失。

### 11.4 登录与安全验收

1. 仅账号密码即可登录；不出现 MFA challenge、绑定页或验证码前置。
2. 错误密码限流与锁定生效；停用账号拒绝登录。
3. 会话 Cookie 为 HttpOnly/SameSite；写请求缺 CSRF 被拒绝。
4. 登录、失败、权限变更、敏感读取/导出有审计，日志不含明文密码。
5. `IAM_MFA_ENABLED=false` 时管理员、HR、工资专员合法 API 不因 MFA 返回 403/202。
6. MFA 开启时历史能力仍可用，但不作为本次上线要求。

### 11.5 工程验收

- 后端：`php artisan test`、Pint、PHPStan、`capability:audit`、`arch:test` 全绿。
- 前端：typecheck、lint、unit、build、E2E 全绿。
- 契约：OpenAPI lint、生成检查、动作门禁、页面/模块门禁全绿。
- 迁移：测试库演练、备份恢复、冲突报告通过。
- 真实栈：登录、关键任务、权限负测、性能与回滚演练通过。
- 文档：ADR、实施书、页面清单、权限矩阵、运维手册与实际实现一致。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 一次性删列导致历史数据丢失 | 工资/合同/审计不可追溯 | 先盘点与备份；冲突即停止；测试库完整演练；生产单独窗口 |
| 权限重排导致角色失去入口 | 业务中断、线下绕过 | 生成旧新授权差异；最小授权；五角色正负测试；管理员保护 |
| 动作清单生成与手写漂移 | 按钮/API/权限再次不一致 | 单一生成源；CI 双向校验；禁止前端手写动作 |
| 页面收敛误删能力 | 功能消失 | 160 条逐项处置表；能力等价比对；用户签认废弃项 |
| 巨型组件拆解引入回归 | 多模块同时故障 | 按纵向任务迁移；每域一条闭环；模块级回滚 |
| 统一弹窗不适合复杂表单 | 用户体验下降 | 复杂流程用抽屉/分步/独立长流程页；ADR 记录例外 |
| 真实栈环境不稳定 | 验收被阻塞 | 固定镜像与种子；就绪检查；失败证据保留；不以 mock 替代 |
| 计划过大导致半成品 | 无法交付 | 四册各自闭环；每册退出条件；未过门禁不进入下一册 |

**回滚原则：**

- 每册、每任务独立提交，可按提交回滚。
- 数据库迁移以快照恢复为主；代码回滚不得依赖已删除列。
- 权限变更保留差异报告与可逆脚本；撤权优先于扩权。
- 页面收敛保留按能力追踪表，不以“恢复 160 个菜单”作为回滚手段。
