# FactoryHR V2.3 M07｜员工入转调离与异动 — 详细实施计划
> **状态：** Proposed — 待用户确认；批准前不得执行。
> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 或 superpowers:executing-plans；步骤用 `- [ ]` 跟踪。

**Goal:** 把九个异动入口收敛为 `/hr/movements` 台账工作区与保留的 `/hr/movements/:id` 详情深链；入职、转正、调岗、调薪、借调、离职、日历成为台账类型 Tab/日历视图，并删除七个旧页，保留状态机与幂等语义。
**Architecture:** Lifecycle 独占异动 intent 与 Workflow Case 生命周期；People 的 Assignment/Terms 只由 Lifecycle effect handler 在批准后写入。前端以一个台账查询组合六类事实（含借调 assignment 投影），详情只读同 case/assignment，不复制审批状态。
**Tech Stack:** Laravel 13 / PHP 8.3 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。
## Global Constraints
- `/hr/movements/{onboarding,probation,transfer,salary-change,secondment,offboarding,calendar}` 全部删除，不保留重定向。
- 保留 `/hr/movements/:id` 深链；详情只读取同一 case/assignment，审批状态只来自 Workflow。
- 所有发起/撤回/决定必须经 `CommandRunner`/Workflow Case，带 Idempotency-Key，重复提交不产生第二 case 或第二 effect。
- 未经批准不更新 assignment/terms；日历必须区分“已生效”与“待生效/待审批”，不能把待审当已异动。
- 新 API 标“新增”并同步 OpenAPI、endpoint matrix、capability、动作清单、生成类型与测试；未执行测试写 `NOT RUN`。

### 0.3 当前缺陷（源码证据）
1. 七个旧页仍由 `frontend/src/router/registry.ts`、`frontend/src/modules/people/catalog.ts` 注册；旧页均为 `PeopleWorkspace` 包装。
2. `MovementWorkspacePage.vue` 已通过 `listWorkflowCases()` 组合五种 case 类型，但借调额外请求 `/v1/lifecycle/secondments`；没有单一“日历”数据源，旧日历页只渲染共享壳。
3. `frontend/src/modules/people/lifecycle/api.ts` 对每种类型分别 `Promise.allSettled()` 调用 `/v1/cases`，重复请求同一列表；失败只拼 partialReason，未统一台账分页。
4. `LifecycleController::cases()` 支持 `case_type/status/employment_id/q/page/page_size`，但 `GET /v1/cases` 前端只按类型五次拉取；台账无真实分页/生效日筛选。
5. `MovementDetailPage.vue` 依赖 `/v1/lifecycle/cases/{id}` 或 workflow case，可深链；日期/生效状态展示已中文，但撤回/决定动作入口分散。
6. `LifecycleServiceProvider::EFFECT_TYPES` 含 `lifecycle.contract_renew`、`lifecycle.rehire`，但 effect handlers 列表只有 Onboarding/Probation/Transfer/Terms/Offboard；对应 case 类型存在审批/effect 风险。
7. `LifecycleCaseListService::paginate()` 只按 `case_type/status/employment_id/q` 过滤 intent 自身字段，`q` 不覆盖员工姓名/工号，故台账快速搜索不完整。
## 1. 目标契约
### 1.1 页面结构
`/hr/movements`：筛选（类型、状态、员工、生效日期区间、关键词）→ 台账/日历视图切换 → 类型 Tab（全部/入职/转正/调岗/调薪/借调/离职）→ 分页；动作“发起异动”打开 `MovementFormDrawer`，选项仅含当前用户 capability 的类型。`/hr/movements/:id`：标题 + 生效状态 Banner + 申请摘要 + 审批轨迹 + 前后快照/生效结果 + 撤回/决定动作。
### 1.2 DTO/API
| 能力 | API | 状态 | capability |
|---|---|---|---|
| 台账/详情 | `GET /v1/lifecycle/cases`、`GET /v1/lifecycle/cases/{caseId}` 或 `GET /v1/cases/{id}` | 现有 | `lifecycle.case.read` |
| 发起入职/转正/调岗/调薪/离职 | `POST /v1/lifecycle/{onboarding|probation-confirmations|transfers|salary-changes|offboardings}` | 现有 | 对应 `lifecycle.*.manage` |
| 借调 | `GET/POST /v1/lifecycle/secondments` | 现有 | `lifecycle.secondment.manage` |
| 撤回/决定 | `POST /v1/cases/{id}/withdraw`、`POST /v1/cases/{id}/decisions` | 现有 | `workflow.case.*` + case action |
| 入职清单 | `GET /v1/employees/{id}/onboarding-checklist`、`PATCH /v1/onboarding-tasks/{id}` | 现有 | `lifecycle.case.read/checklist.manage` |
| 台账统一分页 | `GET /v1/lifecycle/cases?type=&status=&employment_id=&effective_from=&effective_to=&q=&page=&page_size=` | **新增参数** | `lifecycle.case.read` |

台账 DTO：`{case_id,case_no,case_type,kind,employee_id,employee_name,employee_no,application_status,effect_status,effective_date,submitted_at,is_awaiting_me,partial}`；详情：`{case,payload,intent,timeline,effect_result,before,after}`。新增查询参数要真实过滤 intent/People 投影，不能只前端过滤。日历 DTO 复用台账行，另标 `lane:'EFFECTIVE'|'SCHEDULED'|'PENDING_APPROVAL'`；借调 assignment 行用同一结构，`case_id` 可为 null。
### 1.3 状态机
```text
Intent: DRAFT --submit--> SUBMITTED --> IN_APPROVAL --APPROVE--> APPROVED --effect--> EFFECTIVE
Intent: DRAFT|SUBMITTED --withdraw--> WITHDRAWN
Intent: IN_APPROVAL --REJECT--> REJECTED
Effect: PENDING -> APPLIED (once); replay returns prior result; never APPLIED twice
Secondment: SCHEDULED --valid_from--> ACTIVE --valid_to--> COMPLETED
```
`case.application_status`、`effect_status` 只来自 Workflow；LifecycleIntent 只写域投影。并发决定必须 409 `INVALID_CASE_TRANSITION`；effect 重试必须幂等。
### 1.4 权限
| 动作 | capability | 范围 |
|---|---|---|
| 台账/详情/清单读 | `lifecycle.case.read` | COMPANY/MANAGED/SELF（按对象） |
| 发起入职/转正/调岗/调薪/借调/离职 | 各自 `lifecycle.*.manage` | COMPANY（借调另受管理范围） |
| 撤回/决定 | `workflow.case.create/decide/read` + 真实待办 | 当前 assignee / 发起人 |
| 入职清单写 | `lifecycle.checklist.manage` | COMPANY |
