# FactoryHR V2.3 M18｜公告与通知 — 详细实施计划
> **状态：Proposed — 待用户确认。** 本计划不得在规格批准前执行。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.
**Goal:** 将公告审核、受众、阅读记录、模板四个子页面折叠进 `/notices` 的详情 Tab 与动作，保留 `/notifications` 为“我的消息箱”；公告事实只有 Engagement 一个来源，通知只携带公告 ID 与回执要求。
**Architecture:** `Engagement` 独占公告、审批关联、受众快照、阅读回执、模板与通知投递。公告审批由 Workflow Case 记录并通过 `NoticeApprovalPort` 同步，公告页不能自行改审批状态。通知 payload 只保存 `notice_id` 与 `requires_ack`，标题/正文/状态必须回到公告 API 读取，避免第二事实源。`/notifications` 只负责收件箱、已读与按 ID 跳转。
**Tech Stack:** Laravel 13 / PHP 8.3 / MySQL 8.4 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。
## Global Constraints
- 规范优先级：用户裁决 > 本计划 > V2.3 M18 模块规格 > V2.1 设计 > 历史文档。
- 4 个 `FOLD` 公告路由不做重定向；registry、barrel、catalog、Vue 文件与旧测试同时删除。
- 通知不得复制公告标题/正文/状态；前端只能凭 `notice_id` 再读公告并按当前权限处理 403/404。
- 写命令使用 `CommandRunner`/`IdempotencyRunner` + `Idempotency-Key` + `AuditRecorder`；公告审批不得由公告控制器直接改状态。
- 公告发布、阅读导出与模板写入的字段按 P2 处理；受众快照与阅读回执分离。
- 未执行测试、E2E、迁移演练写 `NOT RUN`，不得写“通过”。

## 2. 目标契约
### 2.1 页面结构
```text
/notices
├── 列表：全部 | 待我确认 | 管理视图（草稿/待审/已发布/归档）
├── 工具栏：新建公告、模板设置、归档公告
├── 创建/编辑 Drawer：内容 -> 发布范围（ALL/ORG/ROLE，实时人数）-> 审核要求
└── 详情抽屉 /?notice=:id&tab=content|approval|audience|reads|templates
    ├── content：标题、正文、状态、发布时间
    ├── approval：提交审批、同意/驳回、发布、Workflow 案件链接
    ├── audience：受众类型、组织/角色快照、预览人数
    ├── reads：已读/未读统计、回执列表、导出、催阅
    └── templates：版本化模板列表、发布新版本
/notifications
├── 全部 | 未读 | 已读
├── 逐条已读、批量已读
└── 通知链接：仅用 payload.notice_id 打开 /notices?notice=:id，权限不足 403/404
```
六态：`loading | empty | unconfigured | forbidden | error | success`；模板引用已失效、未选择受众、公告已撤回等使用 `unconfigured` 或稳定中文冲突文案。

### 2.3 状态机与事实边界
```text
公告：DRAFT -> PENDING_APPROVAL -> APPROVED -> PUBLISHED -> ARCHIVED
                 └────────────> REJECTED        └─> RETRACTED
归档：PUBLISHED/RETRACTED -> ARCHIVED；恢复按 archive_previous_status 回到原状态
模板：PUBLISHED(version n) -> 追加 PUBLISHED(version n+1)；旧版本永不改写
通知：unread -> read；不得改变公告状态
```
审批人来自 Workflow Case 当前 `assignee_user_id`；发布者不得自行审批。阅读回执与通知已读分离：阅读回执由公告 acknowledge 产生，通知 read 只影响消息箱。
### 2.4 权限与字段
- 进入：`/notices` 要求 `engagement.notice.read`；`/notifications` 要求 `notification.read`。
- 管理动作：`notice.manage`、`notice.publish`、`notice.export`；审批决定还需 MFA 与 Workflow 指派。
- 字段：公告正文 P1；受众组织/角色 P2；阅读人可以含姓名/员工号 P2；导出白名单之外 422。通知只显示 ID 摘要，不得作为审批或公告事实源。
