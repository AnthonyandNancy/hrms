# FactoryHR V2.3 M14｜社保公积金与福利 — 详细实施计划
> **状态：Proposed — 待用户确认。** 本计划不得在规格批准前执行。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
**Goal:** 把 `/benefits` 做成社保公积金与福利的唯一可写工作区，扩展 `BenefitsPage.vue` 为“法定参数、福利方案、参保、缴费台账”四个 Tab；复用现有 `statutory-parameters` 版本 API 和 `benefits/plans|enrollments|transactions` API，证明参数历史版本不会改变已冻结工资，并让 `/payroll/statutory` 的旧能力只通过 `/benefits` 使用。
**Architecture:** `Payroll/Benefits` 仍是福利方案、参保版本、月度台账与法定参数的唯一写入者。`statutory_parameters` 只保留一套 effective-dated 版本源；`benefit_plans`/`benefit_enrollments`/`benefit_transactions` 不复制法定费率。`BenefitsPage.vue` 只调用既有真实 API，新增的是页面 Tab/权限视图与契约测试，不是第二套 API/表。历史工资通过 `payroll_input_snapshots` 中已快照的参数版本保持冻结。
**Tech Stack:** Laravel 13 / PHP 8.3 / MySQL 8.4 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。

## Global Constraints
- 规范优先级：用户裁决 > 本计划 > V2.3 M14 模块规格 > V2.1 设计 > 历史文档。
- M14 只有一个 KEEP 入口 `/benefits`；`/payroll/statutory` 在 M13 删除，本模块不恢复第二个参数写入口。
- 唯一参数源：`statutory_parameters`（`TAX/SOCIAL_INSURANCE/HOUSING_FUND/ROUNDING`），福利方案不复制费率/基数。
- `Payroll/Benefits` 独占 `benefit_plans`、`benefit_enrollments`、`benefit_transactions`、`statutory_parameters`；其他模块只读投影。
- 金额整数分；费率至少 1e6 缩放字符串；生效日期按公司时区；写命令使用 `CommandRunner`/`IdempotencyRunner`、Idempotency-Key、审计、稳定 409。
- 迁移 forward-only；未执行测试一律写 `NOT RUN`。

## 2. 目标契约
### 2.1 `/benefits` 页面结构
```text
/benefits
├── 法定参数：TAX/SOCIAL_INSURANCE/HOUSING_FUND/ROUNDING 的版本列表、生效区间、证据引用、新建版本 Drawer
├── 福利方案：方案版本、雇主/个人费率、生效区间、方案版本 Drawer
├── 参保登记：员工/方案/基数/生效日版本、按员工查询、维护 Drawer
└── 缴费台账：月度个人/雇主/合计（整数分）、工资批次关联、只读状态
```
`?tab=statutory|plans|enrollments|transactions` 是页面内状态；非法值回落 `plans`。六态 `loading | empty | unconfigured | forbidden | error | success`。`statutory` Tab 只在 `payroll.parameters.read` 时可见；写按钮只在 `payroll.parameters.manage` 时可见，服务端仍校验。
### 2.2 DTO / API（复用现有，不新增第二源）
| 操作 | 状态 | Capability | 说明 |
|---|---|---|---|
| `GET /v1/payroll/statutory-parameters` | 现有，复用 | `payroll.parameters.read` | 返回版本、code、`value_int/value_decimal`、effective、evidence、is_demo |
| `POST /v1/payroll/statutory-parameters` | 现有，复用 | `payroll.parameters.manage` | 原子创建完整参数集版本 + 税 brackets |
| `GET /v1/benefits/plans` | 现有，复用 | `benefit.read` | 版本列表；费率字符串 |
| `POST /v1/benefits/plans` | 现有，复用 | `benefit.manage` | 追加方案版本 |
| `GET /v1/benefits/enrollments` | 现有，复用 | `benefit.read` | 参保版本；基数整数分 |
| `POST /v1/benefits/enrollments` | 现有，复用 | `benefit.manage` | 追加参保版本 |
| `GET /v1/benefits/transactions` | 现有，复用 | `benefit.read` | 月度台账；`payroll_run_id` |
| `POST /v1/benefits/transactions` | 现有，复用 | `benefit.manage` | 月度登记；新增冻结 run 409 |
参数版本请求（沿用现有契约，**不得改名**）：
```json
{
  "parameter_set": "SOCIAL_INSURANCE",
  "version": "SI-2026.2",
  "effective_from": "2026-07-01",
  "effective_to": "2027-06-30",
  "MIN_BASE_CENTS": 400000,
  "MAX_BASE_CENTS": 3000000,
  "EMPLOYEE_RATE": "8.000000",
  "EMPLOYER_RATE": "16.000000",
  "evidence_ref": "董事会 2026-06 决议",
  "is_demo": false
}
```
`TAX` 请求必须同时给 `THRESHOLD_CENTS` 和 `brackets`，税率 `rate_bps` 为整数；服务端按 `parameter_set` 校验完整 code 集，缺一即 422。`version` 是业务版本串，不覆盖已存在版本；同 `parameter_set+code+version+effective_from` 重复 409。响应中金额/基数永远是整数，费率为字符串。
### 2.3 状态机
```text
法定参数：PUBLISHED -> 历史只读（无 UPDATE/DELETE；新版本 append）
福利方案：version n -> version n+1（历史只读，effective_to 由新版本截断）
参保版本：version n -> version n+1（基数变化追加，不覆盖）
月度台账：RECORDED -> 只读；`payroll_run_id` 只能关联未冻结/有效 run，重复关联 409
```
- `statutory_parameters` 模型已有 `updating/deleting` 抛错，**继续使用**。
- 已冻结 run 的输入快照保存参数版本号；之后新增参数版本不改变历史工资。
- 参数版本不许复用已存在的 `version/effective_from` 组合；无参数时薪资计算器 fail closed（既有 `TaxParameterResolver` 行为），不得在 `/benefits` 页面自动填默认费率。
### 2.4 权限与字段
- 参数 Tab：`payroll.parameters.read` 读，`payroll.parameters.manage` 写；福利 Tab：`benefit.read` 读，`benefit.manage` 写；页面入口保留 `benefit.read`，参数 Tab 自己再判 `payroll.parameters.read`。
- 新增 `BENEFITS_ADMIN` 的 `payroll.parameters.manage` 授权（该角色已有 `read`），使“唯一写入口”可实际操作；其他角色不得默认获得。
- 法定参数、方案费率、参保基数、月度缴费为 P2；员工身份字段按 P1；工资批次关联只返回 ID/期间，不返回 P3 明细。
- 冻结 run 的 `POST /v1/benefits/transactions` 若带 `payroll_run_id` 且目标 run 已 `PUBLISHED/PAID/CLOSED`，返回 409 `BENEFIT_PAYROLL_RUN_FROZEN`；已存在台账不得改，重复登记 409。
