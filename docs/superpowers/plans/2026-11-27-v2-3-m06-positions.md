# FactoryHR V2.3 M06｜岗位、职级和任职资格 — 详细实施计划
> **状态：** Proposed — 待用户确认；批准前不得执行。
> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 或 superpowers:executing-plans；步骤用 `- [ ]` 跟踪。

**Goal:** 把五个岗位入口收敛为 `/hr/positions` 唯一工作区；编制、任职资格、职级、在岗人员改为岗位查询 Tab/详情分区，删除四个独立页，并复用 `PositionRequirementsPanel`。
**Architecture:** Organization 独占岗位目录、职级、资格版本与 headcount limit；People 的在岗人数/人员通过 `PositionOccupancyDirectory`/`AssignmentDirectory` 只读投影；查询 Tab 共享同一 `as_of/q/org_unit/status` 上下文，不再各自造列表。
**Tech Stack:** Laravel 13 / PHP 8.3 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。
## Global Constraints
- `/hr/positions/headcount`、`/requirements`、`/grades`、`/staff` 删除，不保留重定向；能力迁入 `/hr/positions?tab=` 与岗位详情分区。
- 岗位编码唯一；资格只追加版本，不覆盖历史；在用职级不能物理删除；在岗人数来自有效 assignment，不得人工写入。
- 新 API/新查询参数标“新增”，同步 OpenAPI、endpoint matrix、capability、动作清单、生成类型与测试。
- 跨域只读投影不得直写 People 表；金额/日期规则适用；未执行测试写 `NOT RUN`。

### 0.3 当前缺陷（源码证据）
1. 四个旧页仍由 `frontend/src/router/registry.ts`、`frontend/src/modules/people/catalog.ts`、`pages/index.ts` 注册，旧页只渲染 `PeopleWorkspace`。
2. `PositionWorkspacePage.vue` 已有岗位表、详情抽屉和 `PositionRequirementsPanel`，但 headcount/staff/grades 仍分散在旧页，panel 只在详情抽屉。
3. `GET /v1/positions` 只接受 `as_of/q`，`frontend/src/modules/people/positions/api.ts` 明确在客户端做 status/org 过滤与分页；`POSITION_LIST_CAPABILITY_NOTE` 还把技术限制暴露给业务用户。
4. `GET /v1/positions/grades` 受 `org.position.grade.manage,COMPANY` 保护；只读岗位用户没有该能力时职级目录回退为 code，页面显示 `position-grade-gap` 技术 errata。
5. `PositionStaffPage` 旧 loader 最多循环 20 个岗位调 `/v1/positions/{id}/staff`，产生 N+1；工作区应只查选中岗位。
6. `PositionController::update()` 仅接受 `title/grade/headcount_limit/status`；表单把 code/org/dates 渲染只读并显示后端缺口文案，无独立停用动作。
7. `PositionCatalogService::versionQualification()` 已正确追加版本并经 `CommandRunner`；不重写，只移动到工作区并补权限/幂等测试。
8. 无新表需求：岗位编制在 `positions.headcount_limit`，资格在 `position_qualifications`，人员来自 assignment。
## 1. 目标契约
### 1.1 页面结构
`/hr/positions`：筛选（业务日期、关键词、部门、状态）→ 岗位表 → 分页；顶部 Tab `catalog|headcount|grades`；选中岗位详情分区 `overview|staff|requirements|headcount`。query `?tab=&position=&detail=` 可刷新/分享；grades 写动作仅对 `org.position.grade.manage` 展示。
### 1.2 DTO/API
| 能力 | API | 状态 | capability |
|---|---|---|---|
| 岗位目录 | `GET /v1/positions?as_of=&q=` | 现有 | `org.position.read` |
| 创建/编辑 | `POST /v1/positions`、`PATCH /v1/positions/{id}` | 现有 | `org.position.manage` |
| 编制/在岗/空缺 | `GET /v1/positions?as_of=` 的 `headcount_limit/occupancy/vacancies` | 现有 | `org.position.read` |
| 在岗人员 | `GET /v1/positions/{id}/staff?as_of=` | 现有 | `org.position.staff.read` |
| 资格版本 | `GET/POST /v1/positions/{id}/requirements` | 现有 | `org.position.qualification.manage` |
| 职级目录 | `GET/POST /v1/positions/grades` | 现有 | `org.position.grade.manage` |
| 列表分页 | `GET /v1/positions?page=&page_size=&sort=` | **新增参数** | `org.position.read` |
| 岗位详情 | `GET /v1/positions/{id}` | 现有 | `org.position.read` |

DTO：`Position{id,code,title,org_unit_id,grade,headcount_limit,occupancy,vacancies,status,valid_from,valid_to}`；Staff `{employment_id,employee_no,person_name,assignment_type,is_primary,valid_from,valid_to}`；Qualification `{id,position_id,version,requirements,effective_from,recorded_at}`。职位编辑只改可写字段；code/org/dates 若需改，必须新增版本命令并标新增。
### 1.3 状态机
```text
Position: ACTIVE --edit title/grade/headcount--> audit fact (same row)
Position: ACTIVE --disable--> DISABLED (history remains readable)
Qualification: version N --POST(effective_from)--> version N+1; prior immutable
Grade: active --toggle--> inactive; grade used by position cannot be physically deleted
Staff: derived from assignment as-of; this module never writes assignment
```
`PATCH` 与 `POST /requirements` 使用 CommandRunner/Idempotency-Key；同 payload 重放返回原版本，不新增第二审计/版本。
### 1.4 权限
| 动作 | capability | 范围 |
|---|---|---|
| 岗位目录/编制读 | `org.position.read` | ORG_UNIT/ORG_SUBTREE/COMPANY |
| 在岗人员 | `org.position.staff.read` | MANAGED/ORG_UNIT/ORG_SUBTREE/COMPANY |
| 岗位写/停用/编制 | `org.position.manage` | ORG_UNIT/ORG_SUBTREE/COMPANY |
| 资格版本 | `org.position.qualification.manage` | ORG_UNIT/ORG_SUBTREE/COMPANY |
| 职级读写 | `org.position.grade.manage` | COMPANY |

```php
  'as_of'=>['nullable',new BusinessDateRule],'q'=>['nullable','string','max:160'],

]);
$query = Position::query()->where('valid_from','<=',$on)->where('valid_to','>',$on)
  ->when($data['org_unit_id']??null, fn($q,$id)=>$q->where('org_unit_id',$id))

$total=(int)(clone $query)->count();
$items=$this->positions->payloads($query->forPage($page,$pageSize)->get()->all(),$on);
return ApiResponse::ok(ApiResponse::list($items,$page,$pageSize,$total));
```
