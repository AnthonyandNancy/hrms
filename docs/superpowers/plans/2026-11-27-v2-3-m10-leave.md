规则 append 请求：`leave_type_id,effective_from,effective_to,applies_to:{scope:"COMPANY"},accrual:{mode,minutes_per_year},carryover,min_notice_days,max_consecutive_days,requires_attachment_over_days,allow_half_day,legal_basis`。`version` 由服务端锁内 `max(version)+1`，客户端传值不可信。
状态机：
```text
申请：SUBMITTED -> APPROVED -> CONSUMED
        └──────> REJECTED/CANCELLED；APPROVED -> REVOKED（销假）
规则：DRAFT -> PUBLISHED -> RETIRED
类型：ACTIVE -> INACTIVE -> ACTIVE
```
SUBMITTED 写 RESERVE；批准写 CONSUME 并释放 RESERVE；撤销 RELEASE；销假 REVERSE。无规则 409 `LEAVE_POLICY_UNPUBLISHED`；交叉重叠 409 `LEAVE_REQUEST_OVERLAP`；冻结期 409 `LEAVE_PERIOD_FROZEN`。
权限：进入 `time.leave.read`；本人 `time.leave.request`；台账 `time.leave.read` + 非 SELF；类型 `time.leave.type.manage`；规则 `time.leave.policy.read/manage`；管理撤销 `time.leave.admin`；汇总 `time.leave.report.read`。on-behalf 锚点仅 `ORG_UNIT|ORG_SUBTREE|COMPANY`，不得授 SELF。余额/原因/附件 P1；工资字段 P3，本模块不读工资表。

## 2.5 唯一事实源与迁移边界

- `leave_types` 只保留“假别身份与展示属性”（code、name、unit、是否法定、是否需要附件、是否允许负数、启停）；不得继续承载额度、适用范围、到期规则、最低提前通知、最大连续天数等规则事实。
- `leave_policy_versions` 保存规则版本事实（额度/accrual、carryover/expiry、applies_to、min notice、max consecutive、附件阈值、法律依据、版本、生效/失效、发布/停用）。
- 迁移回填时，`leave_types` 的 `annual_entitlement_days/expiry_rule_json/legal_basis/version` 只用于构造首个 `leave_policy_versions` 行；回填后这些列保留为兼容只读列但不再写入，后续模块不得从两处读取规则。
- `LeaveRequestService` 必须只经 `LeavePolicyService::effectiveFor()` 取规则；余额与扣减只经 `LeaveLedgerService`。
- 删除或停用 `leave_types` 前必须检查 `leave_policy_versions`、`leave_accounts`、`leave_ledger_entries` 引用；历史行不得物理删除。
- 若真实执行时发现已有其他代码写 `leave_types` 规则列，停止并先补“单写入者”测试，不得直接双写。
