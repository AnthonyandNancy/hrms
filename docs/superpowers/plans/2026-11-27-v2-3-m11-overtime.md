# FactoryHR V2.3 M11｜加班与调休 — 详细实施计划
> **状态：Proposed — 待用户确认。** 本计划不得在规格批准前执行。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
**Goal:** 将五个 overtime 旧入口折叠进 `/overtime`；把代码内置只读加班规则改为 effective-dated 公司版本，确认时快照政策，并证明同一条加班只结算一次、冻结工资后拒绝 PAY 结算。
**Architecture:** `Time/Overtime` 独占 `overtime_requests`、`overtime_records`、`overtime_settlements` 与新增 `overtime_policy_versions`。现有 `overtime_settlements.overtime_record_id` 唯一约束已经保证“PAY 或 TIMEOFF 只一次”，不重写；只补政策版本、确认快照、团队读范围和冻结期间只读契约。Travel 使用独立页面与模块，复用页面是当前主要缺陷。
**Tech Stack:** Laravel 13 / PHP 8.3 / MySQL 8.4 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。

## 2. 目标契约
### 2.1 页面结构
```text
/overtime
├── 我的加班：本人规则摘要、历史、申请 Drawer、审批/确认进度
├── 加班台账：员工/部门/日期/状态筛选、详情、确认行操作
├── 加班规则：公司版本列表、历史、新建 Drawer、retire
├── 加班确认：待确认队列、实际分钟 vs 打卡事实、确认结果
├── 调休余额：额度、获取/使用/到期流水、按员工查询
└── 结算记录：PAY/TIMEOFF 选择、记录、冻结期间只读
```
`?tab=mine|requests|policies|confirm|timeoff|settlement` 仅页面状态，非法值回落 `mine`。六态：`loading | empty | unconfigured | forbidden | error | success`；无公司规则显示 `unconfigured`，不自动套用内置默认。
### 2.2 DTO / API
| 操作 | 状态 | Capability | 说明 |
|---|---|---|---|
| `GET /v1/time/overtime/policies` | 现有，重构 | `time.overtime.read` | 公司版本行；无版本 `items=[]`、`source=COMPANY_VERSION` |
| `POST /v1/time/overtime/policies` | **新增** | `time.overtime.manage` | append 公司规则版本 |
| `POST /v1/time/overtime/policies/{id}/retire` | **新增** | `time.overtime.manage` | 设置 `retired_at`，不删历史 |
| `GET /v1/time/overtime/requests` | 现有，扩展 | `time.overtime.read` | 新增 `view=team` 与员工/状态/日期/分页 |
| `POST /v1/time/overtime/requests` | 现有 | `time.overtime.request` | 本人申请 |
| `POST /v1/time/overtime/requests/{id}/confirm` | 现有，扩展 | `time.overtime.confirm` | 原子写 policy id/snapshot；重复 409 |
| `GET /v1/time/overtime/timeoff-balances` | 现有 | `time.timeoff.read` | TIMEOFF 结算投影，不建余额表 |
| `POST /v1/overtime/records/{recordId}/settlements` | 现有，扩展 | `time.overtime.settle` | 保留唯一约束；新增冻结 409 |
政策 append 请求：`effective_from, effective_to, time_unit_minutes∈{1,5,10,15,30,60}, multiplier, statutory_holiday_multiplier, allow_pay, allow_timeoff, allocation, rounding, legal_basis`。`version` 由服务端锁内 `max(version)+1`，客户端传值不得覆盖；倍率匹配 `/^\d{1,6}\.\d{6,18}$/`，不转 float。
### 2.3 状态机
```text
申请：SUBMITTED? -> APPROVED -> CONFIRMED -> SETTLED(PAY|TIMEOFF)
                         └────> REJECTED/CANCELLED
政策：DRAFT -> PUBLISHED -> RETIRED
结算：无 -> PAY 或 TIMEOFF（终态，不原地改方法）
```
`overtime_records` 只由确认生成一次；同一 record 不同方法再次结算 409 `ALREADY_SETTLED`。目标月份 run 为 `PUBLISHED/PAID/CLOSED` 时 PAY 结算 409 `PAYROLL_PERIOD_FROZEN`；TIMEOFF 不受 PAY 冻结影响但页面明确“仅调休”。
### 2.4 权限与字段
- 本人申请 `time.overtime.request`；读 `time.overtime.read`；确认 `time.overtime.confirm`；结算 `time.overtime.settle`；规则 `time.overtime.manage`；调休读 `time.timeoff.read`。现有能力已存在，不新增重复项。
- SELF 只本人；MANAGED 只直属；ORG_UNIT/ORG_SUBTREE/COMPANY 按 Authorizer；越界 404；确认/结算二次校验记录与范围。
- 规则/结算为 P2；SELF 不返回他人政策快照或结算金额。
