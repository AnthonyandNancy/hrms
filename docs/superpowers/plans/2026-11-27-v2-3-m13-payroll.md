**Goal:** 将 11 个 payroll 旧入口折叠进 `/payroll`（详情保留 `/payroll/runs/:id`）；删除 `/payroll/statutory` 并把能力迁入 `/benefits`；为未版本化的 `payroll_items` 补 forward migration 与 create-version/retire，证明金额整数分、冻结批次不可改写。
**Architecture:** `Payroll` 独占 `payroll_items/versions`、`payroll_schemes`、`payroll_runs`、`payroll_run_employees`、`payroll_input_snapshots`、`payslips`、`payroll_adjustments`、`statutory_parameters`。既有 run 状态机、输入快照与冻结触发器**已满足**冻结核心，不重写；只新增项目版本/停用与报表只读边界。`/benefits` 是参数唯一写入口。
**Tech Stack:** Laravel 13 / PHP 8.3 / MySQL 8.4 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。
## Global Constraints
- 优先级：用户裁决 > 本计划 > V2.3 M13 规格 > V2.1 设计 > 历史文档。
- 旧 URL 不重定向；11 个 `FOLD` 删除并登记目的地；`/payroll/statutory` 能力只迁 `/benefits`，不在 payroll 保留副本。
- 金额一律 `*_cents` 整数；费率/倍率至少 1e6 缩放字符串；禁止 PHP float 参与金额。
- `payroll_runs` 的 PUBLISHED/PAID/CLOSED 冻结与 `payroll_input_snapshots` append-only 不得绕过；项目/方案变更不得改历史批次/工资条。
- 新命令用 `CommandRunner`/`IdempotencyRunner`、`Idempotency-Key`、审计、稳定 409；迁移 forward-only、匿名类；未执行测试写 `NOT RUN`。

## 2. 目标契约
### 页面结构
```text
/payroll
├── 批次：期间/状态筛选、创建、计算、取消/重开、进入详情
├── 配置：项目、方案、员工薪资档案、调薪历史
├── 工资条：已发布批次管理 + 本人入口
└── 报表：汇总/趋势/部门成本/授权导出
/payroll/runs/:id：输入/复核/发放/工资条/导出
```
`?tab=` 仅页面状态，非法值回落首个可见 Tab；六态 `loading|empty|unconfigured|forbidden|error|success`，空项目不得只显示表头。
### DTO / API
| 操作 | 状态 | Capability | 说明 |
|---|---|---|---|
| `GET/POST /v1/payroll/items` | 现有，扩展 | `payroll.run.read/prepare` | 列表返回当前/历史版本；POST 首版由服务端置 version=1 |
| `POST /v1/payroll/items/{id}/versions` | **新增** | `payroll.run.prepare` | 复制并追加版本；锁内自增 |

| `GET/POST /v1/payroll/schemes` | 现有，修正 | `payroll.run.read/prepare` | 服务端版本自增，金额整数分 |

| `GET/POST /v1/payroll/runs[/{id}/...]` | 现有 | 各自 `payroll.run.*` | lock/calculate/review/approve/publish/mark-paid/close/reopen/correct/export |
| `GET /v1/payroll/payslips[/{id}]` | 现有 | `payroll.payslip.read.self` | 本人只本人；未发布不可见 |
| `GET /v1/payroll/reports/summary` | **新增** | `payroll.report.read` | 已发布汇总/趋势/部门成本 |
项目新版本请求（**新增**）：`name,type,taxable,insurable,calculation,formula_json,sort_order,effective_from`。响应 `id,code,version,status,effective_from,effective_to,amount_cents?`；金额 `*_cents` 整数，费率字符串。
### 状态机
```text
批次：DRAFT -> INPUT_LOCKED -> CALCULATED -> REVIEWED -> APPROVED -> PUBLISHED -> PAID -> CLOSED
前序允许 -> CANCELLED；冻结状态不可回退
项目：ACTIVE(v1) -> ACTIVE(vn) -> RETIRED；历史版本只读
输入快照：append-only；锁定后只通过 reopen 生成新 snapshot_version
```
- `PUBLISHED/PAID/CLOSED` 的 run/`payslip_lines` 已由触发器/服务冻结；不得 UPDATE 绕过。
- 项目新版本只影响 `effective_from` 之后方案解析，不重算旧 run。
- 删除 `/payroll/statutory` 不等于删能力；参数仍由 `/benefits` 读写，Payroll 计算只读。
### 权限
`/payroll` 进入 `payroll.run.read`；prepare/review/approve/publish/close/reopen/correct/export 分别控制动作；项目/方案/档案按字段策略。新增 `payroll.report.read`（COMPANY/ORG_SUBTREE，P2）只用于汇总；`payroll.payslip.read.self` 只本人，未发布 404；导出需 `payroll.export` + P3 白名单并审计；`/benefits` 参数沿用 `payroll.parameters.read/manage`。

return DB::transaction(function () use ($itemId, $data, $actorUserId): PayrollItemVersion {
    $item = PayrollItem::query()->whereKey($itemId)->lockForUpdate()->firstOrFail();
    $from = BusinessDate::from((string) $data['effective_from'])->value();
    $overlap = PayrollItemVersion::query()->where('payroll_item_id', $item->id)->whereNull('retired_at')
        ->where('effective_from', '<=', $from)->where('effective_to', '>=', $from)->exists();
    if ($overlap) throw new ConflictException('Item effective range overlaps.', ['reason' => 'PAYROLL_ITEM_VERSION_OVERLAP']);
    $version = ((int) PayrollItemVersion::query()->where('payroll_item_id', $item->id)->max('version')) + 1;
    $row = PayrollItemVersion::query()->create([... 'version' => $version, 'effective_from' => $from, 'effective_to' => (string) ($data['effective_to'] ?? '9999-12-31'), 'status' => 'ACTIVE', 'recorded_at' => $this->clock->now()]);
    $this->audit->record($actorUserId, 'payroll.item.versioned', 'payroll_item', (int) $item->id, after: ['version' => $version]);
    return $row;
});
