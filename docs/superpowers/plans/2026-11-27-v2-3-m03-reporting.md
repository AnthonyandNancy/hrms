# FactoryHR V2.3 M03｜报表与导出中心 — 详细实施计划

> **状态：** Proposed — 待用户确认；本计划不得在规格批准前执行。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将九个报表入口收敛为唯一 `/reports` 工作区，报表类型、查询、字段授权、导出、订阅与导出任务在同一对象上下文中完成；删除八个旧子页。

**Architecture:** Reporting 拥有报表定义、查询、导出与订阅；业务事实只读投影；导出任务在创建与下载两个时点重新校验数据范围与字段策略；前端只消费服务端列定义，不自行拼字段。

**Tech Stack:** Laravel 13 / PHP 8.3 / Vue 3.5 / TypeScript / PHPUnit / Vitest / Playwright。

## Global Constraints

- `/reports/headcount`、`/reports/attendance`、`/reports/payroll`、`/reports/hiring`、`/reports/talent`、`/reports/builder`、`/reports/subscriptions`、`/reports/exports` 全部删除，不保留重定向。
- 工资字段必须按字段策略裁剪；导出下载必须再次校验权限。
- 查询失败不得渲染为空表；未配置报表不得显示 0 行。
- 金额使用整数最小单位，界面格式化为元。
- 未执行测试写 `NOT RUN`。

5. 导出重授权已部分实现，但缺少“撤销权限后旧下载链接失败”的 E2E。

## 1. 目标契约

### 1.1 页面结构

`/reports` 三个区域：

1. 报表目录：按业务域分组（人力资源、考勤假勤、薪资、招聘、绩效培训）；
2. 查询区：期间、组织、员工范围、状态、字段预览；
3. 结果区：预览、导出、订阅、导出任务。

### 1.2 报表定义 DTO

```json
{
  "code": "WORKFORCE_HEADCOUNT",
  "name": "人力资源报表",
  "domain": "PEOPLE",
  "description": "按统计日与组织范围统计在职、入职、离职和岗位结构。",
  "fields": [
    { "key": "employee_no", "label": "工号", "profile": "P1_INTERNAL", "exportable": true }
  ],
  "filters": [
    { "key": "org_unit_id", "label": "组织", "type": "ORG" }
  ]
}
```

禁止返回 `sourceProjection` 给普通业务界面；技术诊断放在管理员页。

### 1.3 导出契约

- 创建：`POST /v1/reporting/exports`
- 下载：`GET /v1/reporting/exports/{jobId}/download`
- 下载时重验：用户、角色版本、数据范围、字段策略、文件归属、有效期、下载次数。

## 3. 权限负测

| 场景 | 预期 |
|---|---|
| 无工资字段权限导出 `net_cents` | 403，导出任务不创建 |
| 创建后被撤字段权限再下载 | 403 |
| 订阅者权限撤销后执行 | 跳过或失败，不发送敏感数据 |
| 无报表能力访问 `/reports` | 403 |
| 查询投影不可用 | 错误态，不显示 0 行 |
