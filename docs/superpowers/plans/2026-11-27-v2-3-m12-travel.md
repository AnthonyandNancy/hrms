# FactoryHR V2.3 M12｜出差管理 — 详细实施计划
> **状态：Proposed — 待用户确认。** 本计划不得在规格批准前执行。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
**Goal:** 将六个 travel 旧入口折叠进 `/travel`；复用既有差旅政策/费用 API；新增变更与考勤关联；审批仍只由真实 Workflow 待办人完成。
**Architecture:** `Time/Travel` 独占 `business_trip_records`、`travel_policies`、`travel_expenses`，新增 `travel_request_changes`、`travel_attendance_links`。政策仍只由 `TravelPolicyController` 追加，费用仍只由 `TravelExpenseController` 登记；审批写 Workflow Case，同事务更新行程和考勤关联。前端收敛为唯一 `/travel` Tab 工作区。
**Tech Stack:** Laravel 13 / PHP 8.3 / MySQL 8.4 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。

## 2. 目标契约
### 页面结构
```text
/travel
├── 我的出差：本人申请、历史、审批进度、发起 Drawer
├── 出差台账：员工/部门/日期/状态筛选；详情 Drawer；变更/销单
├── 差旅政策：城市档位版本、住宿/交通上限、生效日、发布 Drawer
├── 出差审批：真实 Workflow 待办；查看行程；同意/驳回
├── 出差统计：部门/月度次数/天数/人员汇总；明细下钻
└── 费用交接：已批准行程的整数分费用登记、交接人、凭证
```
`?tab=mine|requests|policies|approval|reports|expenses` 仅页面状态，非法值回落 `mine`；`travel_id` 只打开详情 Drawer，不成为新路由。六态 `loading|empty|unconfigured|forbidden|error|success`；无政策显示 `unconfigured`，不伪造限额。
### DTO / API
| 操作 | 状态 | Capability | 说明 |
|---|---|---|---|
| `GET /v1/travel/requests` | 现有，扩展 | `time.travel.read` | 增 `view=team/status/from/to/employment_id/department_id/page/page_size` |
| `POST /v1/travel/requests` | 现有 | `time.travel.request` | 本人申请 |
| `POST /v1/travel/requests/{id}/change` | **新增** | `time.travel.request` | 建变更 Case；批准前不改原行程 |
| `POST /v1/travel/requests/{id}/approve` | 现有，扩展 | `time.travel.approve` | 应用待批变更并刷新考勤关联 |
| `POST /v1/travel/requests/{id}/cancel` | 现有，扩展 | `time.travel.request` | 取消/销单，失效考勤关联 |
| `GET/POST /v1/travel/policies` | 现有，复用 | `time.travel.policy.read/manage` | effective-dated 版本追加 |
| `GET/POST /v1/travel/expenses` | 现有，复用 | `time.travel.expense/expense.manage` | 关联已批准行程/Case，CLAIM_ONLY |
| `GET /v1/travel/reports/summary` | **新增** | `time.travel.report.read` | 部门/月/状态聚合与明细引用 |
变更 `POST .../change` 请求：`from_date,to_date,destination,purpose,reason`。写 `travel_request_changes(original_json,proposed_json,case_id,status)`；批准后把 proposed 写回原 trip，费用仍绑原 `travel_id`。
### 状态机
```text
出差：PENDING_APPROVAL -> APPROVED -> COMPLETED
                     ├─> REJECTED
                     └─> CANCELLED
变更：PENDING -> APPLIED / REJECTED / CANCELLED
考勤关联：ACTIVE -> RETIRED（销单/被新版本替换）
```
只有 Workflow `APPROVED` 能落行程 `APPROVED`；费用仅 `BUSINESS_TRIP.status=APPROVED` 且 `case.isApproved()`。审批/取消同事务维护 `travel_attendance_links`；关联只是日历事实，不伪造打卡或工时。
### 权限
申请/变更/取消 `time.travel.request`；台账/统计 `time.travel.read` + scope；审批 `time.travel.approve`；政策读/写 `time.travel.policy.read/manage`；费用 `time.travel.expense/expense.manage`。新增 `time.travel.report.read`（MANAGED/ORG_UNIT/ORG_SUBTREE/COMPANY，P1）。SELF 只本人，MANAGED 只直属，越界/不存在 404；费用金额/凭证 P2。
