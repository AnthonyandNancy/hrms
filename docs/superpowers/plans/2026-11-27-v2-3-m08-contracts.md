# FactoryHR V2.3 M08｜劳动合同 — 详细实施计划
> **状态：** Proposed — 待用户确认；批准前不得执行。
> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 或 superpowers:executing-plans；步骤用 `- [ ]` 跟踪。

**Goal:** 把六个合同入口收敛为 `/hr/contracts` 台账工作区与 `/hr/contracts/:id` 详情深链；续签、变更/终止、到期、模板成为台账动作/筛选/设置 Tab，删除四个旧页，并确保所有变更只追加版本。
**Architecture:** People 独占合同台账与文档元数据，Lifecycle 通过 `EmploymentContractVersionLedger` 独占版本历史追加；续签/变更/终止均经 `CommandRunner` + Idempotency-Key，审批 effect 只在批准的 Case 上执行。详情读取真实合同与版本历史，不用前端拼接。
**Tech Stack:** Laravel 13 / PHP 8.3 / Vue 3.5 / TypeScript / Element Plus / PHPUnit / Vitest / Playwright / OpenAPI 3.1。
## Global Constraints
- `/hr/contracts/renewals`、`/changes`、`/expiry`、`/templates` 删除，不保留重定向；能力迁入 `/hr/contracts` 与详情动作/设置 Tab。
- 合同编号唯一并绑定 employment_id；续签/变更/终止绝不覆盖原合同或版本历史；删除为软删且保留历史。
- 到期判断使用公司时区业务日期，不能把已过期合同统计为未过期。
- 新 API/参数标“新增”，同步 OpenAPI、endpoint matrix、capability、动作清单、生成类型与测试；未执行测试写 `NOT RUN`。

## 1. 目标契约
### 1.1 页面结构
`/hr/contracts`：筛选（业务日期、员工、状态、到期窗口 30/60/7/已过期、关键词）→ 台账表格 → 分页；顶部 Tab `ledger`、`expiry`、`templates`（模板 Tab 仅 template.manage 可写）。行动作：查看（始终 `/hr/contracts/:id?employment_id=`）、续签（符合条件且 `people.contract.manage`）。详情：摘要、有效期、版本时间线、附件/原文、处理记录；动作“变更合同”“终止合同”“续签”。
### 1.2 DTO/API
| 能力 | API | 状态 | capability |
|---|---|---|---|
| 台账 | `GET /v1/employments/contracts?as_of=&status=&page=&page_size=` | 现有 | `people.contract.read` |
| 到期 | `GET /v1/employments/contracts/expiring?within_days=&as_of=` | 现有 | `people.contract.read` |
| 详情 | `GET /v1/employments/{employmentId}/contracts/{id}` | 现有 | `people.contract.read` |
| 新建/续签 | `POST /v1/employments/{employmentId}/contracts` | 现有 | `people.contract.manage` |
| 版本 | `GET /v1/employment-contracts/{id}/amendments` | 现有 | `people.contract.read` |
| 变更 | `POST /v1/employment-contracts/{id}/amendments` | 现有 | `people.contract.amend` |
| 终止 | `POST /v1/employment-contracts/{id}/terminate` | 现有 | `people.contract.terminate` |
| 模板读 | `GET /v1/contract-templates?code=&status=&page=&page_size=` | 现有 | `people.contract.read` |
| 模板建/发布 | `POST /v1/contract-templates`、`POST /v1/contract-templates/{id}/publish` | 现有 | `people.contract.template.manage` |
| 台账关键词/员工筛选 | `GET /v1/employments/contracts?q=&employment_id=` | **新增参数** | `people.contract.read` |

合同 DTO `{id,employment_id,employee_no,employee_name,contract_no,contract_type,start_date,end_date,signed_on,status,version,previous_contract_id,renewed_by_id,days_to_expiry,terms_summary,work_location,probation_end_date,display_status_label}`；版本 `{id,contract_id,change_type,terms_version,document_version,effective_from,effective_to,reason,snapshot,recorded_at}`；模板 `{id,code,name,version,status,body,published_at}`。新增 `q/employment_id` 必须服务端过滤并进 OpenAPI。
### 1.3 状态机
```text
Contract: DRAFT --activate/sign--> ACTIVE --expiry window--> EXPIRING --date passed--> EXPIRED
Contract: ACTIVE/EXPIRING --renew(reason)--> new ACTIVE version + previous RENEWED
Contract: ACTIVE/EXPIRING --amend(effective_date, changes)--> new AMENDMENT version; same row before snapshot
Contract: ACTIVE/EXPIRING --terminate(date, reason)--> TERMINATED + TERMINATION version (irreversible)
Template: DRAFT --publish--> PUBLISHED; prior PUBLISHED version -> ARCHIVED
```
每次 version append 必须写 `employment_contract_versions` 并通过 `EmploymentContractVersionLedger`；重复 Idempotency-Key 返回原结果；终止后不得再续签/变更。
### 1.4 权限
| 动作 | capability | 范围 |
|---|---|---|
| 台账/详情/版本/附件读 | `people.contract.read` | SELF/MANAGED/ORG_UNIT/ORG_SUBTREE/COMPANY |
| 新建/续签 | `people.contract.manage` | ORG_UNIT/ORG_SUBTREE/COMPANY |
| 变更 | `people.contract.amend` | COMPANY |
| 终止 | `people.contract.terminate` | COMPANY |
| 模板读 | `people.contract.read` | COMPANY |
| 模板建/发布 | `people.contract.template.manage` | COMPANY |
| 附件下载 | `people.document.download` | 与合同读取范围一致 |
