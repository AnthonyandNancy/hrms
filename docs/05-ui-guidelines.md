# HRMS UI 规范（Task 8A 前端基线）

适用版本：`frontend/` 0.1.0 · Vue 3 + Element Plus · zh-CN 主文案，技术代码/能力码使用英文。
本文件是界面实现与评审的共同基线；视觉调整不能改变状态语义、授权边界或金额/时间口径。

## 1. 布局与信息层级

### 桌面端（≥ 1180px）

- 固定左侧导航 248px，可折叠至 76px；顶栏 72px；内容区最大宽度 1480px。
- 页面结构固定为：面包屑 → 页面标题与一句业务说明 → 操作区 → 筛选区 → 数据/工作区。
- 专业工具保持信息密度：列表使用表格，不用大卡片逐条堆叠；卡片只用于重复指标、摘要和对话框。
- 主内容区背景 `#f2f5f3`，面板白色、1px 边框、8px 圆角；不使用嵌套卡片。
- 品牌色 `#0f4c5c`，强调色 `#b7791f`。状态色只用于状态标记，不用于装饰性大面积填充。
- 页面标题 22–28px，面板标题 15px，表体 12–13px，辅助文字 10.5–11.5px；正文行高 1.55–1.75。
- 主要操作在标题右侧或表单底部；危险操作（驳回、撤回、回收、发布）必须二次确认并说明不可逆后果。

### 平板/移动端（≤ 960px / ≤ 640px）

- ≤ 960px：侧边栏变为抽屉，顶栏出现菜单按钮；双栏/三栏降为单栏。
- ≤ 640px：页面标题与操作区纵向排列；筛选器占满宽度；对话框宽度 `calc(100vw - 24px)`。
- 表格必须横向滚动，不允许压缩到文字重叠或隐藏关键列；滚动区可键盘聚焦，并带“可横向滚动”区域标签。
- 360px 宽度下必须仍可完成：登录、看工作台、审批、请假、查看工资条、导出对话框。
- 触控目标不小于 32×32px；文字不得被截断成不可理解的片段，长文本可换行或省略并提供完整值。

## 2. 状态语言

### 2.1 两条状态线必须分开

| 概念 | 代码 | 中文 | 含义 |
| --- | --- | --- | --- |
| 申请状态 | `DRAFT` | 草稿 | 尚未提交 |
| 申请状态 | `SUBMITTED` | 已提交 | 已进入流程，等待处理 |
| 申请状态 | `IN_APPROVAL` | 审批中 | 当前节点待审批 |
| 申请状态 | `APPROVED` | 已通过 | 审批决定已产生；**不代表业务已生效** |
| 申请状态 | `REJECTED` | 已驳回 | 审批拒绝，无业务效果 |
| 申请状态 | `WITHDRAWN` | 已撤回 | 申请人撤回 |
| 生效状态 | `SCHEDULED` | 待生效 | 已排定未来生效时间 |
| 生效状态 | `APPLIED` | 已生效 | 业务事实已改变 |
| 生效状态 | `FAILED` | 生效失败 | 决定已记录但业务效果失败，可重试 |
| 生效状态 | `REVERSED` | 已冲正 | 原业务效果已由反向记录冲正 |
| 无生效要求 | `null` | 无生效要求 | 该申请不会改变业务事实 |

规则：

1. 任何页面不得使用单一绿色“已完成”同时表达审批通过与业务生效。
2. 列表、详情、时间线、通知和导出说明中，必须能同时看到“申请状态”和“生效状态”。
3. `APPROVED + SCHEDULED` 显示为“已通过 / 待生效”，不得显示为“已完成”。
4. `APPROVED + FAILED` 必须显示失败原因、原数据未修改、重试入口（有权限时）。
5. 状态不能只靠颜色表达：`StatusBadge` 始终包含文字、符号（✓、◷、!、↺）与 `data-status-*` 属性。
6. 颜色 token：成功 `#1f6b4a`、警告 `#8a5300`、危险 `#9b2c2c`、信息 `#1d5a78`、中性 `#667b80`。文字与背景对比度 ≥ 4.5:1。
7. 工资批次使用自身状态机（DRAFT → INPUT_LOCKED → … → CLOSED），不得借用“申请状态”；发布/发放/关账分别呈现。
8. 考勤使用“正常出勤/迟到/缺勤/休假/远程/休息/法定节假日”，同时给文字和说明。

## 3. 掩码与敏感字段

字段档位：

| 档位 | 界面策略 | 导出 |
| --- | --- | --- |
| P0_PUBLIC | 明文 | 允许 |
| P1_INTERNAL | 默认部分遮罩；按能力可查看 | 需导出能力 |
| P2_SENSITIVE | 默认遮罩；独立、逐字段查看 | 仅独立导出能力 |
| P3_RESTRICTED | 不显示、不可搜索/排序/导出 | 禁止 |

实现规则：

- 遮罩值由服务端投影返回；前端不得用算法“补全”遮罩，也不得把手机号/身份证等完整值放进列表接口。
- `MaskedField` 始终显示字段标签、“已遮罩”标签和字段档位提示。遮罩字段增加 `aria-label`，说明该值已遮罩。
- “查看完整值”只在具备对应字段能力时出现；点击后必须填写业务目的，服务端记录“谁、何时、哪个字段、哪个对象、目的”的审计事件。
- 后端返回的 `MaskedFieldValue` 是唯一可信来源。HTTP 模式下通过 `POST /people/employees/{id}/fields/{field}/reveal` 获取，组件不做本地解密。
- 隐藏（P3）字段不得进入筛选、排序、列表列、导出字段选择器或错误提示。
- 导出对话框只列 `exportable=true` 的字段；被排除字段需明确告知数量，不显示字段名或猜测内容。

## 4. 金额、日期与时间

- 金额从整数分（minor units）格式化，显示为 `¥1,234.56`；禁止把浮点计算结果直接展示。负数显示 `-¥5.00` 并使用危险色。
- 金额列右对齐，使用 tabular numbers；合计与明细使用同一来源。
- 业务日期（`YYYY-MM-DD`）按日历日直接格式化，不构造本地 `Date`，避免时区漂移。
- 记录时间以 UTC 传输（ISO-8601），显示时转换为 `company_profile.timezone`（演示：`Asia/Shanghai`），并在相关面板标注时区。
- 时间线、审计、发放时间显示 `YYYY-MM-DD HH:mm`；相对时间只作辅助，必须保留可访问的绝对时间。
- as-of 查询必须在页面上明确显示“按某日期的有效关系”；移动/未来生效不得改写历史视图。

## 5. 权限与导航

- 导航项由服务端页面授权（`role_pages`）+ 能力投影驱动；`Can`/`ActionGate`/`CapabilityGate` 只做 UI 辅助隐藏，不能代替 API 授权。
- 前端不得把能力判断当作授权真相；每个页面/操作都必须依赖后端 401/403/404 结果。
- 无能力时：
  - 页面路由回退到“无访问权限”页，说明可申请授权；
  - 操作按钮不出现或禁用，并说明所需能力码；
  - 越权 ID 访问返回 404，前端显示统一“未找到或超出数据范围”文案，不泄露记录存在性。
- 授权绑定必须展示：对象 → 能力 → 锚点（本人/组织/全公司）→ 字段档位 → 业务目的 → 有效期 → 状态；锚点没有“法人/租户”。
- 角色授权页固定四个 Tab：页面权限、按钮权限、数据权限、字段权限。
- 可展开菜单必须显示 chevron，并维护 `aria-expanded`、`aria-controls`；当前分组自动展开，子项 `aria-current="page"`。
- 页面内所有非 GET 操作按钮必须由 `PageActionSpec` 声明能力，并通过 `Can`/`ActionGate` 渲染；无能力时不渲染可点击控件。
- 撤权后下一次请求应被拒绝；不得出现前端缓存继续放行的情况。

## 6. 加载、空、错误与反馈

| 状态 | 文案 | 交互 |
| --- | --- | --- |
| 加载 | “正在加载…” | 骨架行 + `role=status` / `aria-live=polite`；不要用空白页 |
| 空 | 针对页面具体说明，如“当前条件下没有审批案例” | 提供清除筛选或下一步操作 |
| 错误 | “暂时无法加载” + 一句原因 + 重试 | `role=alert`；保留已知数据并标注新鲜度 |
| 会话过期 | “登录状态已失效，为保护数据安全，请重新登录。” | 引导回登录页，不弹技术细节 |
| 403 | “你没有执行此操作的权限。如确需访问，请提交授权申请。” | 显示能力码（可选）与返回工作台 |
| 404 | “未找到该记录，可能已被撤回、移出你的数据范围，或链接有误。” | 不泄露存在性 |
| 409 | “数据状态已发生变化，请刷新后重试。” | 保留用户输入 |
| 422 | “提交内容未通过校验，请检查标记的字段。” | 字段旁显示具体中文错误 |
| 429 | “操作过于频繁，请稍后再试。” | 禁用重复提交 |
| 网络 | “网络连接失败，请检查网络后重试。” | 重试按钮 |
| 500/503 | “系统暂时无法完成该操作，请稍后重试并联系管理员。” | 显示 request_id 便于支持 |

- 表单错误同时使用文字、边框和 `aria-invalid`，不能只变红。
- 成功反馈说明业务后果，例如“申请已提交；审批通过后才会占用余额”，不要说“已完成”。
- 删除/撤回/发布等不可逆或高影响动作必须二次确认，并说明历史保留方式。
- 数据新鲜度用 `FreshnessNote` 展示“数据更新于 UTC→公司时区”；投影延迟不得假装实时。

## 7. 无障碍（WCAG 2.2 AA 基线）

- 每个输入有可见 `<label>` 或 `aria-label`；按钮使用动词短语；仅图标按钮必须有 tooltip 与可访问名称。
- 保留可见焦点环（2px 品牌色，2px offset）；不得用 `outline: none` 消除焦点。
- 提供“跳到主要内容”链接；路由切换后将焦点移到主内容标题附近。
- 状态、错误、加载结果使用 `aria-live`/`role=alert`；对话框打开时焦点受限，关闭后归还触发元素。
- 表格有 `<caption>`/`aria-label`、表头 `scope=col`；横向滚动区域可键盘聚焦。
- 不以颜色作为唯一信息：状态有文字+符号，图表有表格替代文本和数据明细。
- 文本对比度 ≥ 4.5:1；大字 ≥ 3:1；焦点/边框对比度 ≥ 3:1。
- 支持键盘完成登录、MFA、导航、审批、请假、导出；不得设置不可见的键盘陷阱。
- 尊重 `prefers-reduced-motion`。

自动化：Playwright + axe 对登录、工作台、仪表盘、案例详情、工资批次详情做 critical/serious 级别零违规门禁；人工评审仍需覆盖键盘与读屏场景。

## 8. 内容与语言

- 主界面 zh-CN；能力码、请求编号、字段档位、CSV 字段名保留英文技术标识。
- 不使用 Lorem ipsum 或纯占位符；所有空状态必须说明“为什么为空、下一步做什么”。
- 不用“全部完成/成功”掩盖多状态；用具体名词：“审批通过”“工资已发布”“已发放”“已关账”。
- 文案中的日期写全（`2026年11月23日`）；表格可缩写但要有 `title`/可访问全称。
- 演示数据必须为合成姓名与明显虚假编号，不得包含真实个人信息。

## 9. 组件约定

- `StatusBadge`：`kind="application|effect"` 必填；`showLabelPrefix` 在双状态并列时使用。
- `MaskedField`：接收服务端 `MaskedFieldValue`；没有 `canReveal` 时不渲染查看按钮。
- `MoneyText`：接收整数 `cents`；传入非整数抛错而不是静默四舍五入。
- `AsOfDatePicker`：统一 as-of 日期选择，显示当前业务日期；默认禁止未来日期，业务允许时显式开启。
- `CapabilityGate`：仅做 UI 隐藏；页面仍需处理后端拒绝。
- `Timeline`：按 `occurredAt` 排序，区分申请/生效/系统三条轨道；时间使用公司时区。
- `DataTable`：统一搜索、加载/空/错、分页与横向滚动；不把权限过滤写进表格组件。
- `LoadingState` / `EmptyState` / `ErrorState`：每个数据页面必须至少覆盖三者。

## 10. 响应式与评审清单

提交评审前检查：

- [ ] 1440×900 与 390×844 下无横向页面溢出（表格内部滚动除外）。
- [ ] 360px 下标题、标签、金额、状态徽标不重叠、不截断关键内容。
- [ ] 所有主流程可用键盘完成，焦点可见。
- [ ] 登录、工作台、员工目录、组织树、审批、请假、考勤、工资、工资条、权限治理、公告、仪表盘、报表均有真实数据。
- [ ] 页面明确区分申请状态与生效状态。
- [ ] 金额全部来自整数分；时间全部从 UTC 转公司时区。
- [ ] P2 字段默认遮罩，查看需目的与审计。
- [ ] 加载、空、错误、403、404 状态有明确文案与恢复动作。
- [ ] axe 无 critical/serious 违规；颜色对比达标。
- [ ] UI 能力隐藏与后端授权拒绝行为一致。

## 11. 本任务边界

Task 8A 的 Playwright 套件运行在 mock 模式，覆盖登录→仪表盘→下钻、审批通过、生效失败重试入口、工资批次→工资条、导出目的对话框、角色导航、MFA step-up 与 axe smoke，不依赖后端。

真实后端 E2E（权限差异、余额更新、调岗生效、工资发布、导出下载与审计、撤权即时生效）是后续集成任务；不得把 mock 通过视为真实接口验收通过。OpenAPI 生成类型也需在 Task 1B 的 `docs/openapi/openapi.yaml` 合并后接入，当前 `src/api/contracts.ts` 是冻结接口的适配边界，不与 OpenAPI 竞争。
